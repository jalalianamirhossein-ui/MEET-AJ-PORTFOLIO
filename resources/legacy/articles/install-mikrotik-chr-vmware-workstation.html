MikroTik CHR Lab on VMware Workstation: Isolation and Validation

Build an isolated CHR lab with explicit VMnet mapping, restricted management, license-aware measurements and recoverable test configuration.

MikroTik

Meet AJ technical article

Start reading

Introduction

An incorrectly bridged lab can inject test DHCP or routing into the company network. Deploy CHR with explicit VMnet mapping and restricted management access.

Practical Example

A NAT VMnet supplies WAN and a separate Host-only network supplies LAN. The team validates branch exports and Firewall behavior before an upgrade.

Prerequisites

RouterOS CHR v7 and a licensed Workstation build supported on the host. Record exact router patch and Workstation build.

Lab recommendation: 2 vCPU, 1 GiB RAM, at least 1 GiB disk and two vNICs for CHR. Throughput depends on the host and license.

Official MikroTik VMDK, Virtual Network Editor and administrator rights for VMnet creation. Use the initial console and organizational password/license policies.

Architecture / Design

NAT VMnet → CHR ether1; Host-only with VMware DHCP disabled → CHR ether2 → client VM. Map management and test networks by name and MAC in inventory.

Installation / Configuration

Download the official CHR VMDK and verify its published checksum. Record filename/hash. Create a VM using the existing virtual disk and confirm NIC mapping from its first-boot console.

The lab WAN is 192.168.100.10/24, gateway 192.168.100.2; match these to the actual NAT VMnet. LAN is 10.99.0.1/24.

/interface ethernet print detail
/user set [find name=admin] password="REPLACE_WITH_UNIQUE_ADMIN_SECRET"
/system identity set name=CHR-STAGING
/ip address add address=192.168.100.10/24 interface=ether1 comment="LAB WAN"
/ip address add address=10.99.0.1/24 interface=ether2 comment="LAB LAN"
/ip route add dst-address=0.0.0.0/0 gateway=192.168.100.2
/ip dns set servers=192.168.100.2 allow-remote-requests=no
/ip firewall filter add chain=input connection-state=established,related action=accept
/ip firewall filter add chain=input in-interface=ether2 src-address=10.99.0.0/24 action=accept
/ip firewall filter add chain=input action=drop
/ip firewall filter add chain=forward connection-state=established,related action=accept
/ip firewall filter add chain=forward in-interface=ether2 out-interface=ether1 action=accept
/ip firewall filter add chain=forward action=drop
/ip firewall nat add chain=srcnat src-address=10.99.0.0/24 out-interface=ether1 action=masquerade
/ping 192.168.100.2 count=3
/system license print

This ruleset targets a clean IPv4 lab. Restrict IPv6 separately. The gateway should respond and a LAN client using 10.99.0.1 should traverse allowed paths. SSH/WinBox must not be reachable from the new WAN.

Security Hardening

Do not bridge test VMnets to a company NIC. Set a unique admin secret and disable unused services. Protect the host console with access controls/MFA; snapshots contain credentials.

Monitoring

Record host/VM CPU, dropped packets and interface counters. The Free license limits throughput; document the license with every benchmark.

Troubleshooting

Missing IP requires checking vNIC mapping, connection-at-power-on and VMnet subnet. Gateway timeout suggests MAC/VMnet or host Firewall. Limited speed requires both license and host-load checks. Never point the default route to CHR’s own address.

Backup / Recovery

Take a labeled pre-test snapshot and export configuration outside the VM. A snapshot is not an independent backup. Review clone/license/system-ID recovery against CHR documentation. Never run duplicate-IP clones simultaneously.

Best Practices

Use this lab to validate syntax and behavior. Production dataplanes require supported hypervisors and workload-based sizing.

Legacy Versions and Compatibility

Free licenses limit upload to 1 Mbps per interface; P1/P10/P-Unlimited have different conditions. A desktop Workstation baseline is not an HA design.

Frequently Asked Questions

Can a Workstation lab replace a production router?

No. It validates configuration; HA, support and capacity require separate design.

Why is throughput low?

Check both the CHR license tier and host resources.
