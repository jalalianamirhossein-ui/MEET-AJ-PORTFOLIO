Install MikroTik CHR on VMware Workstation

Build NAT and host-only networks, boot the official VMDK, configure routing and firewall rules, and check license limits.

CHR for RouterOS testing

CHR runs RouterOS as a virtual machine. On Workstation, use a NAT WAN and host-only LAN to test routing and firewall behavior without injecting lab DHCP or routes into the company network.

Map vNICs to router interfaces

Record each VMnet and vNIC MAC, then match them to router interfaces. Do not assume Workstation adapter order always matches ether1 and ether2. Clients use CHR as their gateway, with router NAT sending permitted traffic to the lab WAN.

Lab WAN and LAN topology

Connect ether1 to NAT and ether2 to host-only, with a client VM on the LAN. Disable VMware DHCP on that LAN when CHR or another service will manage it.

Image and VM resources

Use CHR v7 and a Workstation build compatible with the host. Record both builds for reproducible tests.

This lab allocates 2 vCPUs, 1 GiB RAM, at least 1 GiB disk and two vNICs. Actual throughput depends on host resources and licensing.

Obtain the official MikroTik VMDK and access to Virtual Network Editor. Perform initial configuration through the console and change the administrator password before network access.

License throughput limits

Free licensing limits upload to 1 Mbps per interface. P1, P10 and P-Unlimited have different limits. Desktop Workstation is not an HA router design.

Create the VM and configure the IPv4 lab

Download the official CHR VMDK. Match any publisher-provided checksum and record a local hash. Use Existing Virtual Disk in the new VM and match vNIC MACs through its console.

Sample WAN is 192.168.100.10/24 via 192.168.100.2, with LAN 10.99.0.1/24. Obtain actual subnet, gateway and DNS from Virtual Network Editor and replace example values. 

/interface ethernet print detail
/user set [find name=admin] password="REPLACE_WITH_UNIQUE_ADMIN_SECRET"
/system identity set name=CHR-STAGING
/ip address add address=192.168.100.10/24 interface=ether1 comment="LAB WAN"
/ip address add address=10.99.0.1/24 interface=ether2 comment="LAB LAN"
/ip route add dst-address=0.0.0.0/0 gateway=192.168.100.2
/ip dns set servers=192.168.100.2 allow-remote-requests=no
/ip firewall filter add chain=input connection-state=established,related action=accept
/ip firewall filter add chain=input in-interface=ether2 src-address=10.99.0.0/24 action=accept
/ip firewall filter add chain=input action=drop
/ip firewall filter add chain=forward connection-state=established,related action=accept
/ip firewall filter add chain=forward in-interface=ether2 out-interface=ether1 action=accept
/ip firewall filter add chain=forward action=drop
/ip firewall nat add chain=srcnat src-address=10.99.0.0/24 out-interface=ether1 action=masquerade
/ping 192.168.100.2 count=3
/system license print

Rules target a fresh IPv4 lab. Restrict IPv6 separately. Test the gateway and a client using 10.99.0.1 plus valid DNS. SSH/WinBox must remain inaccessible from WAN.

Keep the lab isolated

Do not bridge lab VMnets to the company NIC. Use unique credentials and disable unused management services. Snapshots contain credentials and require sensitive-backup controls. The example firewall covers IPv4 only.

Measure throughput and resource use

During throughput tests, record host/CHR CPU and drop counters. Attach the license tier to the result. Distinguish Free-license limits from CPU shortages.

Unreachable gateways or low throughput

For an unreachable gateway, check connection-at-power-on, MAC, VMnet and subnet. Static configuration does not imply DHCP. Clients need 10.99.0.1 as gateway and a valid DNS server. For low throughput, inspect licensing and host load. The default route points to the NAT gateway, not CHR itself.

Snapshots and off-VM exports

Take a pre-test snapshot and keep exports outside the VM. A snapshot does not survive host-storage loss independently. After cloning, check IP, system ID and license requirements. Never start duplicate-IP VMs together.

What the lab establishes

Use the lab to check syntax and configuration behavior. Do not generalize Workstation throughput or reliability to RouterBOARD or production hypervisors.

Frequently Asked Questions

Can a Workstation lab replace a production router?

No. It validates configuration. HA, support and capacity require separate design.

Why is throughput low?

Check both the CHR license tier and host resources.
