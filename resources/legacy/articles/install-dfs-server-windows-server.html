Configure DFS Namespaces and Replication on Windows Server

Create a domain namespace, configure DFS-R, verify initial synchronization and diagnose backlog and SMB access.

Microsoft

Meet AJ technical article

Start reading

How DFS-N and DFS-R differ

DFS Namespaces provide stable paths to shares. DFS Replication copies files between servers. Namespaces also work without replication. For two branches, configure the access path and then content synchronization. Replicated deletions and overwrites require independent backups.

Referrals and replication paths

Clients obtain SMB targets through DFS-N. Separately, DFS-R replicates closed files. Multi-master does not provide shared cross-site locking. This design is unsuitable for live databases or files requiring cross-site locks.

Example: a shared path for two branches

Company/Data has FS01 and FS02 targets. FS01 supplies the initial data. FS02 remains offline for referrals during initial sync, and users must not write directly to its share.

Prepare AD, storage and shares

Use AD DS-joined Windows Server 2022/2025 with DFSN and DFSR modules. Store replicated content on NTFS. DFS-R does not support ReFS.

Allow data, staging and conflict/deleted space on both file servers. Staging size depends on large files and change volume rather than one universal allocation.

Replace corp.example.com, FS01, FS02, D: and CORP\FileUsers with actual values. Prepare NTFS paths, shares, role-installation rights and AD delegation.

Domain namespaces and PrimaryMember

This example uses a domain-based namespace. Assess standalone-namespace availability separately. PrimaryMember selects the initial-sync source rather than a permanent replication leader.

Share, NTFS and firewall permissions

Share and NTFS permissions must both permit the intended access. End users need no namespace-root writes. Scope SMB and required RPC to members and approved subnets, aligning dynamic RPC with network policy. Review signing and access auditing.

Create the namespace and replication group

Prepare roles and paths on both file servers. D: must be suitable NTFS storage. CORP FileUsers represents the actual organizational group.

Install-WindowsFeature FS-DFS-Namespace,FS-DFS-Replication -IncludeManagementTools
New-Item -ItemType Directory -Path 'D:\DFSRoots\Company','D:\Data' -Force | Out-Null
New-SmbShare -Name Company -Path 'D:\DFSRoots\Company' -ReadAccess 'CORP\FileUsers'
New-SmbShare -Name Data -Path 'D:\Data' -ChangeAccess 'CORP\FileUsers'
Get-WindowsFeature FS-DFS-Namespace,FS-DFS-Replication

Design/apply NTFS ACLs with the data owner. Share permissions do not grant NTFS access. Continue from a management host with modules and delegation.

Import-Module DFSN
Import-Module DFSR
New-DfsnRoot -Path '\\corp.example.com\Company' -TargetPath '\\FS01\Company' -Type DomainV2
New-DfsnRootTarget -Path '\\corp.example.com\Company' -TargetPath '\\FS02\Company'
New-DfsnFolder -Path '\\corp.example.com\Company\Data' -TargetPath '\\FS01\Data'
New-DfsnFolderTarget -Path '\\corp.example.com\Company\Data' -TargetPath '\\FS02\Data' -State Offline
New-DfsReplicationGroup -GroupName 'Company-Data'
New-DfsReplicatedFolder -GroupName 'Company-Data' -FolderName 'Data'
Add-DfsrMember -GroupName 'Company-Data' -ComputerName 'FS01','FS02'
Add-DfsrConnection -GroupName 'Company-Data' -SourceComputerName 'FS01' -DestinationComputerName 'FS02'
Set-DfsrMembership -GroupName 'Company-Data' -FolderName 'Data' -ComputerName 'FS01' -ContentPath 'D:\Data' -PrimaryMember $true -Force
Set-DfsrMembership -GroupName 'Company-Data' -FolderName 'Data' -ComputerName 'FS02' -ContentPath 'D:\Data' -Force

Add-DfsrConnection creates the reverse connection by default. Inspect Get-DfsrConnection. Do not repeat creation on existing deployments. AD propagation/initial sync takes time. PrimaryMember selects the initial source only. FS02 starts Offline so clients receive no referrals before acceptance. Also restrict direct user access to its share during initial sync. Accept only after a closed canary file reaches FS02 with the same hash and both backlogs reach zero. Run the following commands to bring that target Online only after these checks pass.

Set-DfsnFolderTarget -Path '\\corp.example.com\Company\Data' -TargetPath '\\FS02\Data' -State Online
Get-DfsnFolderTarget -Path '\\corp.example.com\Company\Data'

Backlog and staging pressure

Measure backlog in both directions and correlate its trend with disk space and DFS Replication events. Brief backlog after writes is expected. Sustained growth indicates replication is falling behind or connectivity is impaired.

Accept initial sync before user access

Close a test file on FS01 and verify the matching hash on FS02. Both backlogs must drain during the controlled test. Only then bring the FS02 target online.

Stale files with a healthy namespace

When the path opens but content is stale, separate SMB reachability from DFS-R health. Inspect connections and backlog from a module-equipped host, then read events on the affected member.

Get-DfsrConnection -GroupName 'Company-Data'
Get-DfsrBacklog -GroupName 'Company-Data' -FolderName 'Data' -SourceComputerName 'FS01' -DestinationComputerName 'FS02' -Verbose
Get-DfsrBacklog -GroupName 'Company-Data' -FolderName 'Data' -SourceComputerName 'FS02' -DestinationComputerName 'FS01' -Verbose
Get-WinEvent -LogName 'DFS Replication' -MaxEvents 30
Test-NetConnection FS02 -Port 445

Get-DfsrBacklog returns a limited file list. Check verbose output for the full count. Open files, insufficient staging and content freshness need different corrections. Do not delete the DFS-R database as a generic repair.

Restore without unintended overwrite propagation

Use independent VSS-aware file backups and an AD/namespace protection plan. Restore selected files to an isolated path, compare ACLs and hashes, then control their return to replication. Rebuild failed members through the documented non-authoritative procedure. RPO depends on actual backups.

Frequently Asked Questions

Is DFS-R a backup replacement?

No. Deletes/overwrites can replicate. Independent backups remain necessary.

Is PrimaryMember a permanent leader?

No. It selects the initial-sync source. Normal replication is multi-master.
