Windows Hardware Inventory with systeminfo, CIM and DxDiag

Choose hardware tools, export PowerShell JSON inventory, and interpret VM, RAID and DxDiag limitations.

Microsoft

Meet AJ technical article

Start reading

Choose the tool for the question

CIM provides structured model, RAM and BIOS data. Systeminfo gives a quick overview, while DxDiag targets DirectX, graphics and audio drivers. None alone establishes RAID health or a VM host’s physical capacity.

Which Tool Fits the Investigation?

ToolBest fitLimit
CMD / systeminfoOS, CPU and RAM overview during supportText output is awkward for structured inventory
PowerShell / CIMAutomated inventory and JSON exportsAccuracy depends on providers and permissions
DxDiagDirectX, graphics, audio and driver investigationDoes not replace CMDB or RAID health checks

CMD is a shell, not a hardware API. The utility it runs determines the information source. WMIC may be absent or disabled on newer Windows versions, so use CIM for new automation. Do not assume DxDiag is present on Server Core.

Modules and read access

The script targets x64 Windows PowerShell 5.1 on Windows 11 or Server 2022/2025 with CimCmdlets and Storage.

Run on the existing host with a writable report location. Compare VM provider data with hypervisor inventory.

Local reads usually work with standard privileges. Remote CIM requires authorized sessions. Do not assume DxDiag exists on Server Core.

WMIC and systems without a GUI

WMIC is deprecated and one host’s availability does not establish fleet availability. Prefer CIM for new automation. DxDiag applies to systems with its graphics components.

Providers and inventory snapshots

CIM/Storage providers supply data for JSON snapshots and CMDB baseline comparison. Specialized GPU/RAID telemetry needs vendor tooling too.

Example: inventory before an upgrade

Compare model, BIOS, cores and RAM with CMDB, retaining collection UTC. VM serials might be virtual identifiers. Use hardware-management consoles for chassis identity.

Collect JSON and a DxDiag report

Run the complete read-only script in x64 Windows PowerShell 5.1. It writes to the user TEMP directory. Substitute an approved location if policy requires it.

$ErrorActionPreference = 'Stop'
$InventoryPath = Join-Path $env:TEMP ('Inventory-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.json')
$Inventory = [ordered]@{
    CollectedUtc = [DateTime]::UtcNow.ToString('o')
    Computer = Get-CimInstance Win32_ComputerSystem | Select-Object Name,Manufacturer,Model,TotalPhysicalMemory
    OS = Get-CimInstance Win32_OperatingSystem | Select-Object Caption,Version,BuildNumber,LastBootUpTime
    CPU = @(Get-CimInstance Win32_Processor | Select-Object Name,NumberOfCores,NumberOfLogicalProcessors)
    Memory = @(Get-CimInstance Win32_PhysicalMemory | Select-Object Manufacturer,PartNumber,Capacity,Speed)
    BIOS = Get-CimInstance Win32_BIOS | Select-Object Manufacturer,SMBIOSBIOSVersion,SerialNumber
    Disks = @(Get-PhysicalDisk | Select-Object FriendlyName,MediaType,Size,HealthStatus)
    Video = @(Get-CimInstance Win32_VideoController | Select-Object Name,DriverVersion)
}
$Inventory | ConvertTo-Json -Depth 6 | Set-Content -LiteralPath $InventoryPath -Encoding UTF8
Get-Content -LiteralPath $InventoryPath -Raw | ConvertFrom-Json | Select-Object CollectedUtc,Computer
Get-FileHash -LiteralPath $InventoryPath -Algorithm SHA256

JSON includes a UTC timestamp and named objects. Capacity and Size are bytes. Divide by PowerShell 1GB for GiB. Verify model and serial against CMDB/vendor consoles. Run DxDiag only where the GUI/binary exists and the report directory is writable.

On systems with DxDiag, these commands create and check a text report. This is separate from the inventory script and suits graphics-driver diagnostics.

$DxReport = Join-Path $env:TEMP ('DxDiag-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.txt')
Start-Process -FilePath "$env:WINDIR\System32\dxdiag.exe" -ArgumentList @("/t", '"' + $DxReport + '"') -Wait -WindowStyle Hidden
Get-Item -LiteralPath $DxReport -ErrorAction Stop

Null values and RAID abstractions

Do not treat null as zero. VM providers might omit physical information. Get-PhysicalDisk might show controller abstractions. Remote access denied requires session/permission checks. Missing DxDiag on Server Core is not an inventory-script failure.

Inventory differs from health checks

Compare RAM/BIOS changes with approved records. Disk HealthStatus is not complete SMART or RAID-controller health. Use relevant telemetry for health and inventory for ownership/capacity.

Units and limited-precision properties

Script Capacity/Size values are bytes. Dividing by PowerShell 1GB yields GiB. Do not use AdapterRAM to size modern GPUs. Confirm through vendor tools.

Reports and remote sessions

Hostnames and serials disclose organizational assets. Avoid public shares. Use least-privilege Kerberos/TLS remote CIM. Do not enable Basic without TLS to fix access denied.

Retain snapshots and recovery records

Retain JSON, hashes and timestamps according to retention. Hardware replacement also requires drivers, firmware, RAID configuration and data backups. Inventory lists assets rather than providing restoration.

Frequently Asked Questions

Is DxDiag appropriate for every server?

No. It targets graphics/DirectX and may be absent on Server Core.

Does Healthy HealthStatus guarantee RAID health?

No. Inspect controller telemetry and vendor tools as well.
