Windows Hardware Information: CMD vs PowerShell vs DxDiag

Collect timestamped Windows inventory, distinguish VM abstractions from physical hardware and validate capacity against CMDB and vendor telemetry.

Microsoft

Meet AJ technical article

Start reading

Introduction

A screenshot is insufficient for capacity decisions. Collect comparable, timestamped inventory and distinguish physical hardware from virtual-machine representations.

Which Tool Fits the Investigation?

ToolBest fitLimit
CMD / systeminfoOS, CPU and RAM overview during supportText output is awkward for structured inventory
PowerShell / CIMAutomated inventory and JSON exportsAccuracy depends on providers and permissions
DxDiagDirectX, graphics, audio and driver investigationDoes not replace CMDB or RAID health checks

CMD is a shell, not a hardware API; the utility it runs determines the information source. WMIC may be absent or disabled on newer Windows versions, so use CIM for new automation. Do not assume DxDiag is present on Server Core.

Practical Example

Before a fleet upgrade, operations compares BIOS, cores and RAM with organizational inventory. A VM serial number need not identify the physical chassis.

Prerequisites

Windows Server 2022/2025 or Windows 11 with 64-bit Windows PowerShell 5.1. Server cmdlets require their corresponding roles and modules.

Use an authorized existing host; diagnostic tools need no additional hardware. A sample lab VM can use 2 vCPUs, 4 GiB RAM and 60 GiB storage.

Use x64 PowerShell, CimCmdlets and Storage. Local reads usually need standard access; remote collection needs delegated permissions and protected WinRM. DxDiag applies to Desktop Experience.

Architecture / Design

CIM/Storage providers → JSON snapshot → CMDB → baseline comparison. DxDiag targets client graphics/DirectX issues; verify professional GPU capacity using vendor tools.

Installation / Configuration

Run the complete read-only script in x64 Windows PowerShell 5.1. It writes to the user TEMP directory; substitute an approved location if policy requires it.

$ErrorActionPreference = 'Stop'
$InventoryPath = Join-Path $env:TEMP ('Inventory-' + (Get-Date -Format 'yyyyMMdd-HHmmss') + '.json')
$Inventory = [ordered]@{
    CollectedUtc = [DateTime]::UtcNow.ToString('o')
    Computer = Get-CimInstance Win32_ComputerSystem | Select-Object Name,Manufacturer,Model,TotalPhysicalMemory
    OS = Get-CimInstance Win32_OperatingSystem | Select-Object Caption,Version,BuildNumber,LastBootUpTime
    CPU = @(Get-CimInstance Win32_Processor | Select-Object Name,NumberOfCores,NumberOfLogicalProcessors)
    Memory = @(Get-CimInstance Win32_PhysicalMemory | Select-Object Manufacturer,PartNumber,Capacity,Speed)
    BIOS = Get-CimInstance Win32_BIOS | Select-Object Manufacturer,SMBIOSBIOSVersion,SerialNumber
    Disks = @(Get-PhysicalDisk | Select-Object FriendlyName,MediaType,Size,HealthStatus)
    Video = @(Get-CimInstance Win32_VideoController | Select-Object Name,DriverVersion)
}
$Inventory | ConvertTo-Json -Depth 6 | Set-Content -LiteralPath $InventoryPath -Encoding UTF8
Get-Content -LiteralPath $InventoryPath -Raw | ConvertFrom-Json | Select-Object CollectedUtc,Computer
Get-FileHash -LiteralPath $InventoryPath -Algorithm SHA256

JSON includes a UTC timestamp and named objects. Capacity and Size are bytes; divide by PowerShell 1GB for GiB. Verify model and serial against CMDB/vendor consoles. Run DxDiag only where the GUI/binary exists and the report directory is writable.

Security Hardening

Serial numbers, hostnames and inventory reveal organizational topology. Restrict report access. Remote CIM requires an approved least-privilege session and WinRM TLS/Kerberos; do not enable Basic without TLS.

Monitoring

Alert on unauthorized RAM/BIOS changes and disk health rather than every inventory snapshot. Use Zabbix for health and CMDB for ownership. Healthy HealthStatus is not complete SMART or RAID-controller evidence.

Troubleshooting

Null CIM values in a VM may reflect provider limitations; distinguish Unknown from actual zero. Get-PhysicalDisk can abstract disks behind RAID, so consult controller telemetry. Missing DxDiag on Server Core is not an inventory failure. Remote access denied calls for session/permission checks, not Firewall removal.

Backup / Recovery

Inventory does not change service state. Retain JSON and hashes according to policy. Hardware recovery also needs firmware, drivers, RAID configuration and application backups; a serial number is not a restore procedure.

Best Practices

Use CIM for automation and vendor tools for specialized telemetry. Do not size modern GPUs from the low-precision AdapterRAM property.

Legacy Versions and Compatibility

WMIC is deprecated; its presence on one host does not establish fleet availability. This script uses CIM. Server Core and graphical workstations have different scopes.

Frequently Asked Questions

Is DxDiag appropriate for every server?

No. It targets graphics/DirectX and may be absent on Server Core.

Does Healthy HealthStatus guarantee RAID health?

No. Inspect controller telemetry and vendor tools as well.
