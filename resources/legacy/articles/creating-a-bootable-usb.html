Create a Bootable USB for Ubuntu or Windows Server

Verify an ISO, write it with Rufus, match UEFI and Secure Boot settings, and troubleshoot boot and storage detection.

What bootable media provides

A bootable USB starts an installer or recovery environment. It needs a trusted ISO, suitable media and settings that match the target firmware. Copying an ISO file onto an ordinary USB does not make it bootable.

ISO, UEFI and media layout

A trusted checksum compares the download with the publisher’s file. The writer then builds bootable media for UEFI or BIOS to load. Installation media supplies startup tools. Application data, encryption keys and backups must be available separately.

Example: prepare recovery media

Prepare media before a replacement server is needed. Label it with the operating system, ISO version and last boot-test date. Keep the image hash with the download record so the media is reproducible.

Before writing the USB

Download the ISO from Ubuntu or Microsoft. This example covers Ubuntu 24.04 LTS and Windows Server 2022/2025. The desktop Windows Media Creation Tool is not a Server ISO download tool.

Choose capacity for the image and writing method. A 16 GiB USB suits many images, but check the actual size. Confirm operating-system support for the target storage controller and NIC.

Run an official Rufus build on Windows. Preserve any USB data elsewhere, then check the target disk number, size and serial. Writing the image erases the selected USB.

Legacy BIOS compatibility

For a Legacy BIOS machine, select its compatible layout. Do not choose GPT or MBR solely from the operating-system name. Target firmware and the image’s writing instructions determine the choice.

Image trust and credential protection

Obtain the ISO and writer from official sources. Keep unattended-installation passwords off shared media. Leave Secure Boot enabled for compatible images and investigate signature failures through image and trust-chain checks.

Verify the ISO and write it with Rufus

Obtain the ISO and checksum through official channels. Replace the sample IsoPath with your existing file. These commands read hashes and disk identity only. 

$IsoPath = 'C:\InstallMedia\ubuntu-24.04-live-server-amd64.iso'
Get-Item -LiteralPath $IsoPath -ErrorAction Stop | Select-Object Name,Length
Get-FileHash -LiteralPath $IsoPath -Algorithm SHA256
Get-Disk | Select-Object Number,FriendlyName,SerialNumber,BusType,Size

The SHA256 must match the publisher exactly. A hash you generate yourself detects later changes but does not authenticate the download.

Identify the USB by size/serial in Rufus and select the ISO. Check target firmware and distribution guidance. GPT generally suits UEFI, while ISO/DD mode follows the image’s instructions.

Recheck the target before Start because its data is erased. After writing/ejecting, select the USB from the test machine’s temporary boot menu.

Keep Secure Boot enabled for compatible images. Check storage/NIC detection in the installer and recovery access to a test backup. Do not install onto production disks.

Boot-test the target hardware

Use the temporary boot menu on a test machine matching the target model. Reaching the installer is only the first check. Verify disk and NIC detection and recovery-environment access to a test backup. Record the result and date.

Common media-test mistakes

A successful laptop boot does not establish server-storage compatibility. Test equivalent hardware and stop before installing onto a data-bearing disk.

When the USB does not boot

If the USB is absent from the boot menu, try another port and match UEFI/BIOS mode to Rufus settings. If the installer misses storage, inspect controller drivers and mode rather than formatting disks. Secure Boot errors require image-signature and compatibility checks. FAT32 does not accept a single file larger than 4 GiB. Use a compatible writer workflow or Microsoft’s documented method for Windows images containing large files.

Rebuild media and prepare restore

Retain the ISO, publisher checksum, writer version and settings to rebuild damaged media. Before an incident, use the recovery environment to test access to backups, encryption keys and required drivers.

Frequently Asked Questions

Is installation USB a server backup?

No. It supplies installation/recovery tools. Application data needs separate backup.

Must Secure Boot be disabled?

Only for a documented incompatibility and an approved decision. Keep it enabled when compatible.
