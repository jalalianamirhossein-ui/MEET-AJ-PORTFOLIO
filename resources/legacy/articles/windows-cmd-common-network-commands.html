Windows Network Commands for DNS, TCP and SMB Diagnostics

Find the failing layer with ipconfig, nslookup and Test-NetConnection, then inspect listeners and SMB permissions.

Microsoft

Meet AJ technical article

Start reading

Ping, DNS and TCP establish different facts

For failed connections, inspect addressing/DNS, then routes and the service port. Successful ping proves neither TCP access nor SMB authorization. Avoid release/renew or stack resets before collecting server evidence.

Example: an inaccessible server share

An application cannot reach files01.corp.example.com over SMB. Test DNS and TCP/445 from its subnet. Record resolved names/addresses to separate wrong DNS from firewall failure.

Investigation through share authorization

The client resolves names, selects route/interface and reaches the TCP listener. SMB then checks identity, share and NTFS permissions. Each failed stage requires a different correction.

CMD and PowerShell on the affected host

Examples target Windows 11 and Windows Server 2022/2025 with x64 Windows PowerShell 5.1. Run CMD and PowerShell blocks in their respective shells.

These tools require no extra compute allocation. Run checks through the affected client’s actual path.

Status reads usually need standard privileges. Route/firewall changes require elevation. Replace sample domains/IPs with actual targets.

Windows modules and other PowerShell platforms

The example NetTCPIP/SMB cmdlets are Windows-specific. PowerShell on Linux does not provide the same modules. CMD diagnostics remain useful, while configuration-reset commands do not belong at the start of investigation.

Address, route and port commands

Capture evidence in CMD first. The internal domain below is a placeholder. 

ipconfig /all
route print
arp -a
nslookup files01.corp.example.com
tracert -d 10.20.30.20
netstat -ano

Use PowerShell to test TCP and routing. TcpTestSucceeded: True establishes TCP connectivity, not SMB permissions. 

$Target = 'files01.corp.example.com'
Resolve-DnsName $Target -Type A
Test-NetConnection $Target -Port 445 -InformationLevel Detailed
Get-NetIPConfiguration
Get-SmbConnection

Create a unique evidence directory. External programs have their own exit codes. 

$ReportPath = Join-Path $env:TEMP ('Network-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $ReportPath -ErrorAction Stop | Out-Null
ipconfig /all | Out-File (Join-Path $ReportPath 'ipconfig.txt') -Encoding utf8
route print | Out-File (Join-Path $ReportPath 'routes.txt') -Encoding utf8
Test-NetConnection $Target -Port 445 | Export-Clixml (Join-Path $ReportPath 'tcp445.xml')

Flush DNS only after comparing suspected stale cache entries with authoritative responses. Repeat the same query and application test afterwards.

DNS timeout, closed port or access denied

DNS timeout with IP connectivity requires resolver/53/suffix checks. Failed TCP with working ping suggests listeners or ACLs. SMB access denied with working TCP points to identity and share/NTFS. 

Get-NetTCPConnection -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
$Listener = Get-NetTCPConnection -LocalPort 445 -State Listen -ErrorAction SilentlyContinue | Select-Object -First 1
if ($null -ne $Listener) {
    Get-Process -Id $Listener.OwningProcess
} else {
    Write-Warning 'No TCP/445 listener found on this host'
}
Get-WinEvent -LogName 'Microsoft-Windows-SMBClient/Connectivity' -MaxEvents 20 -ErrorAction SilentlyContinue

Inspect listeners on the file server, not the client. Empty output means no matching listener on that host. Unresponsive tracert hops alone do not prove application loss because ICMP might be limited.

Reachability differs from service function

Separate TCP probes from functional SMB tests. Correlate latency, reconnects and network events with incident timing. Monitor from a subnet representative of user access.

Protect diagnostic reports

Reports disclose hostnames and internal networks. Restrict access. Wi-Fi exports with key=clear expose secrets. Avoid passwords in net use/command lines and do not disable firewalls to investigate.

Limited corrections and retesting

Record prior routes/rules and prepare change-specific rollback. Release and netsh int ip reset interrupt management. Use console recovery when required. Repeat the same name, port and application tests after correction.

Hostnames and IPs in authentication

IP tests help isolate DNS, but SMB by IP might change Kerberos behavior. Do not assume IP and hostname tests are equivalent. Netstat/PID output is only a snapshot.

Frequently Asked Questions

Does successful ping prove SMB is healthy?

No. Test TCP/445, authentication and permissions independently.

Should DNS cache be cleared first?

No. Record and compare cached and resolver responses before clearing it.
