Windows Network Incident Runbook: DNS, TCP, SMB and Evidence

Diagnose Windows connectivity layer by layer, preserve evidence before clearing caches and distinguish TCP reachability from SMB authorization.

Microsoft

Meet AJ technical article

Start reading

Introduction

Successful ping, correct DNS and a reachable TCP service establish different facts. Identify the failing layer before using release/renew or resetting a server network stack.

Practical Example

An application server cannot access files01.corp.example.com over SMB. Test private DNS and TCP/445 from the application subnet to the file server.

Prerequisites

Windows Server 2022/2025 or Windows 11 with 64-bit Windows PowerShell 5.1. Server cmdlets require their corresponding roles and modules.

Use an authorized existing host; diagnostic tools need no additional hardware. A sample lab VM can use 2 vCPUs, 4 GiB RAM and 60 GiB storage.

CMD and PowerShell are built in. Status reads generally need no Administrator rights. Route/Firewall changes require elevation and an approved change.

Architecture / Design

Client → DNS → selected route/interface → Firewall → TCP listener → SMB authentication → share/NTFS. The failing stage determines which team owns the correction.

Installation / Configuration

Capture evidence in CMD first. The internal domain below is a placeholder.

ipconfig /all
route print
arp -a
nslookup files01.corp.example.com
tracert -d 10.20.30.20
netstat -ano

Use PowerShell to test TCP and routing. TcpTestSucceeded: True establishes TCP connectivity, not SMB permissions.

$Target = 'files01.corp.example.com'
Resolve-DnsName $Target -Type A
Test-NetConnection $Target -Port 445 -InformationLevel Detailed
Get-NetIPConfiguration
Get-SmbConnection

Create a unique evidence directory. External programs have their own exit codes.

$ReportPath = Join-Path $env:TEMP ('Network-' + (Get-Date -Format 'yyyyMMdd-HHmmss'))
New-Item -ItemType Directory -Path $ReportPath -ErrorAction Stop | Out-Null
ipconfig /all | Out-File (Join-Path $ReportPath 'ipconfig.txt') -Encoding utf8
route print | Out-File (Join-Path $ReportPath 'routes.txt') -Encoding utf8
Test-NetConnection $Target -Port 445 | Export-Clixml (Join-Path $ReportPath 'tcp445.xml')

Flush DNS only after comparing suspected stale cache entries with authoritative responses. Repeat the same query and application test afterwards.

Security Hardening

Do not include Wi-Fi exports with key=clear in support bundles: they expose secrets. Avoid plaintext net use credentials on the command line; prefer Kerberos with a hostname and the current account. Do not disable the Firewall to troubleshoot.

Monitoring

Measure availability and TCP service health separately in Zabbix. Record SMB latency, reconnects and errors. Correlate DNS/network changes with incident timestamps and keep sensitive interface output in restricted tickets.

Troubleshooting

DNS timeout with IP connectivity suggests resolver, port 53 or suffix issues. Failed TCP with successful ping suggests a listener or Firewall/ACL problem. SMB access denied with working TCP points to identity and share/NTFS permissions.

Get-NetTCPConnection -State Listen | Select-Object LocalAddress,LocalPort,OwningProcess
$Listener = Get-NetTCPConnection -LocalPort 445 -State Listen -ErrorAction SilentlyContinue | Select-Object -First 1
if ($null -ne $Listener) {
    Get-Process -Id $Listener.OwningProcess
} else {
    Write-Warning 'No TCP/445 listener found on this host'
}
Get-WinEvent -LogName 'Microsoft-Windows-SMBClient/Connectivity' -MaxEvents 20 -ErrorAction SilentlyContinue

Inspect the listener on the file server. An absent listener produces an empty query and a script warning. Unresponsive tracert/pathping hops do not prove application packet loss; routers may rate-limit ICMP.

Backup / Recovery

Diagnostics introduce no service state. Save route/Firewall snapshots before changes and plan rule-specific rollback. ipconfig /release and netsh int ip reset can interrupt management; use them only with console access and a recovery plan. Retain evidence securely.

Best Practices

Test hostname and IP separately. SMB by IP can change Kerberos authentication behavior. netstat/PID output is a snapshot rather than conclusive malware evidence.

Legacy Versions and Compatibility

NetTCPIP cmdlets are available on Windows; PowerShell Core on other operating systems does not provide the same modules. Legacy CMD diagnostics remain useful, while mutations require preflight checks.

Frequently Asked Questions

Does successful ping prove SMB is healthy?

No. Test TCP/445, authentication and permissions independently.

Should DNS cache be cleared first?

No. Record and compare cached and resolver responses before clearing it.
