Ubuntu Production Time: Chrony, Offset Monitoring and NTP Troubleshooting

Operate Chrony on Ubuntu with approved NTP sources, source selection checks, offset alerts and controlled recovery from clock drift.

Linux

Meet AJ technical article

Start reading

Introduction

Clock skew can disrupt Kerberos, TLS, log ordering and replication. A timezone change does not correct the underlying clock; inspect sources, offsets and synchronization separately.

Practical Example

Two internal NTP servers use different upstream sources. Application and database servers use them; central logs use UTC timestamps.

Prerequisites

Ubuntu Server 24.04 LTS, Bash 5 and systemd. Record installed package patches with dpkg-query before making changes.

Example lab capacity: 2 vCPUs, 2 GiB RAM and 20 GiB storage. These are planning assumptions, not vendor minimums; size the service for measured load.

Use sudo, chrony and UDP/123 access to organizational NTP. 10.20.30.53 and .54 are example sources.

Architecture / Design

Authoritative time → internal NTP → chronyd client → kernel clock → application. Timezones change display; clock changes affect workloads.

Installation / Configuration

Record the current state. Only one daemon should own synchronization. Installing chrony normally replaces timesyncd, but verify the resulting service states.

timedatectl status
date -u --iso-8601=seconds
sudo apt-get update
sudo apt-get install -y chrony
systemctl is-active chrony systemd-timesyncd
sudo cp -a /etc/chrony /root/chrony-before-change

Review existing pool/server lines and generated sourcedir entries in /etc/chrony/chrony.conf. Remove conflicting sources only after identifying their ownership. These complete source lines replace public sources with approved internal ones.

server 10.20.30.53 iburst
server 10.20.30.54 iburst
sudo chronyd -p -f /etc/chrony/chrony.conf
sudo systemctl restart chrony
chronyc sources -v
chronyc tracking
sudo timedatectl set-timezone Asia/Tehran
date -u --iso-8601=seconds

Expect a source marked ^*, Reach approaching 377 over multiple polls and Leap status: Normal. Reverse DNS may change the displayed source name. Do not run makestep on production with a large offset until its effects on databases and scheduling have been assessed.

Security Hardening

An NTP client should not accidentally become a public time server. Restrict egress to approved sources. Where authenticated time is required, design NTS with a supporting server. Two servers with the same upstream dependency do not provide source diversity.

Monitoring

Monitor offset, stratum, Reach and source changes. An offset above 100 ms for five minutes is an example alert; sensitive workloads need explicit thresholds. Zabbix or a Prometheus exporter must not treat an active process as evidence of synchronization.

Troubleshooting

^? means a source is not yet usable; inspect UDP connectivity, DNS and the source clock. ^x can identify an inconsistent source.

chronyc sources -v
chronyc sourcestats -v
chronyc tracking
sudo journalctl -u chrony -n 80 --no-pager

Reach zero with an active daemon means polls are not succeeding. Repeated VM clock jumps require reviewing hypervisor time synchronization and assigning a single owner. Changing timezone does not repair an expired TLS certificate.

Backup / Recovery

This procedure introduces no application data state. Version Chrony configuration, timezone policy and source inventory. Restore prior sources during rollback and inspect tracking. After prolonged downtime, confirm synchronization before starting sensitive workloads. Manually stepping time is not database recovery.

Best Practices

Use UTC for logs and local timezones for display. Manual clock changes and NTP-source changes need their own workload assessment and change record.

Legacy Versions and Compatibility

timesyncd remains an option for simple clients; this baseline uses chrony. timedatectl timesync-status reports timesyncd status and does not establish Chrony health.

Frequently Asked Questions

Does a wrong timezone cause TLS failure?

TLS relies on the actual clock; timezone settings change only its display.

Does an active chrony service mean it is synchronized?

No. Check selected sources, offset and Leap status.
