Use whitelisted full, differential and log backups, Agent jobs, chain-aware retention and restore tests for Jira and Confluence.

Automated backups must lead to a working restore

SQL Server Agent schedules backups, but job success does not guarantee service recovery. Jira and Confluence need coordinated databases, application files and attachments. This guide pairs whitelists, jobs, audit and cleanup with restore testing.

Manual backup suits individual changes. Routine protection needs automation, failure alerts and freshness checks for every database. A .bak extension is not integrity evidence.

RPO limits data loss and RTO limits whole-service restoration time, including retrieval, restore, validation and startup. Agree these targets with the service owner and measure them in drills.

Replicas propagate destructive changes too. Snapshots and replication do not replace backup history and independent copies outside primary storage.

Versions, service identities and implementation scope

  • This scenario uses standalone SQL Server 2019/2022 on Windows with Standard, Enterprise or Developer. Developer is nonproduction only. Express lacks SQL Server Agent and requires a separately designed scheduler such as Windows Task Scheduler.
  • Agent must be running with an appropriate startup setting. This implementation does not target Azure SQL Database, Availability Groups or UNC storage. AG deployments require separate replica-policy and SQL-version assessment.
  • The Database Engine service identity writes backups. A CmdExec proxy creates folders and performs cleanup. Permissions for one identity do not substitute for the other.
  • Grant the engine required reads/writes on dedicated backup paths and the proxy folder-creation/file-deletion rights. Avoid Everyone and broad grants. Restrict the script directory to proxy Read/Execute and DBA/system-administrator modifications.
  • PowerShell uses Windows PowerShell 5.1 and built-in SqlClient. The SqlServer module is unnecessary. Integrated Security, TLS encryption and certificate validation are enabled. Replace localhost with an instance/FQDN matching a trusted certificate. Do not toggle TrustServerCertificate to conceal trust errors.
  • The eight whitelist names are examples. Disable absent databases before testing. The procedure does not silently skip them. System databases are rejected: protect master, model and msdb separately. Tempdb cannot be backed up.

COMPRESSION reduces backup size and IO at a CPU cost. Measure duration and CPU before enabling it during busy periods and check edition/version support. Official documentation

A backup from a newer SQL Server engine does not restore to an older engine. Prepare the restore destination with compatible versions and required certificates before an incident.

Design schedules and recovery chains for Jira and Confluence

Assume DB-Jira and DB-Confluence run on a standalone SQL Server. Target roughly fifteen-minute RPO and an initial sixty-minute RTO. Actual restore measurements must validate RTO. Database size, network throughput and log count influence it.

Type Schedule Purpose
Full Backup Daily at 01:00 Recovery base and differential baseline
Differential Backup 07:00, 13:00 and 19:00 Changes since the last ordinary full. Less restore work
Transaction Log Backup Every fifteen minutes, around the clock Changes between data backups and point-in-time recovery
Retention and Cleanup Thirty-day window. Daily cleanup at 05:00 Remove expired files while preserving the chain required throughout the window

A differential is cumulative from its base full, not from the previous differential. Restore the compatible full, latest appropriate differential and required logs in LSN order. For a 14:10 incident, review the 01:00 full, 13:00 differential and subsequent logs. The recoverable endpoint depends on the last healthy log and, where possible, a tail-log backup rather than the incident clock time alone. Official documentation

A fifteen-minute schedule does not guarantee RPO: runtime, failure, delayed secondary copies and missing logs affect actual loss. SQL Server permits full and log backups concurrently. This procedure coordinates full/differential per database without making log backups wait behind a long full.

Schedules use the SQL server’s local clock. Filenames and audit use UTC. Record NTP/timezone in the runbook. Jira/Confluence also require coordinated Application Home, Shared Home, attachments and configuration according to their installed-version guidance.

Choose recovery models before enabling log jobs

Model Log Backup Recovery Scope
SIMPLE Not supported Existing full/differential only. No arbitrary point-in-time recovery
FULL Required for this policy Point-in-time recovery with an intact log chain
BULK_LOGGED Supported Cannot stop within a log containing minimally logged operations

SIMPLE still logs transactions. Its inactive log can be reused after checkpoint when no blocker remains, and it does not preserve a transaction-log backup chain. BACKUP LOG is therefore unavailable. FULL is selected for these Jira/Confluence databases because changes between data backups must be recoverable. Official documentation

After SIMPLE changes to FULL or BULK_LOGGED, a valid full or differential data backup must establish the log chain. This runbook takes a fresh ordinary full for an explicit differential/recovery baseline. This is not a requirement to take full after every model change: FULL-to-BULK_LOGGED transitions do not break the chain like SIMPLE. Take a log backup before leaving FULL/BULK_LOGGED. Returning from SIMPLE requires a new chain. Official documentation 

SELECT name,recovery_model_desc,log_reuse_wait_desc
FROM sys.databases WHERE name IN (N'DB-Jira',N'DB-Confluence');
GO
ALTER DATABASE [DB-Jira] SET RECOVERY FULL;
ALTER DATABASE [DB-Confluence] SET RECOVERY FULL;

These commands deliberately change only the two scenario databases. Decide the other whitelist members’ models separately. BULK_LOGGED is not a permanent log-size fix. Accept its recovery limitations before bulk operations.

Per-database paths and storage capacity 

D:\SQLBackup
├── DB-Jira
│   ├── FULL
│   ├── DIFF
│   └── LOG
└── DB-Confluence
    ├── FULL
    ├── DIFF
    └── LOG

Per-database paths simplify restore selection, capacity checks and cleanup audit. Full/differential use .bak. Logs use .trn. Names include database, type, UTC milliseconds and GUID, preventing manual runs/retries from overwriting earlier files.

D: is only an example path. Different drive letters do not establish independent storage. Shared disks/LUNs still create a common failure point. Give multiple instances separate roots and management databases to avoid mixed audit/files.

Procedure, whitelist and folder provisioning

This file creates DBAOperations, the whitelist, audit table and stored procedure. It selects explicit requested names rather than all server databases. COMPRESSION/CHECKSUM are always enabled. TRY/CATCH records each database failure, attempts remaining members and fails the step if any attempt fails.

The procedure validates paths and rejects system databases, snapshots, offline databases and AG members. LOG on SIMPLE is an error. A PowerShell step creates folders without xp_cmdshell/xp_create_subdir. The T-SQL job runs as a trusted DBA identity with backup/VERIFYONLY rights. A more restricted design requires module signing and permission tests.

CREATE OR ALTER PROCEDURE dbo.usp_BackupWhitelist
    @BackupType varchar(4),
    @BackupRoot nvarchar(200) = N'D:\SQLBackup',
    @Verify bit = 1,
    @EncryptionCertificate sysname = NULL
AS
BEGIN
    SET NOCOUNT ON;
    IF @@TRANCOUNT > 0 THROW 51000, 'Run backups outside a user transaction.', 1;
    SET @BackupType = UPPER(@BackupType);
    IF @BackupType IS NULL OR @BackupType NOT IN ('FULL','DIFF','LOG')
        THROW 51001, 'BackupType must be FULL, DIFF or LOG.', 1;
    IF @Verify IS NULL THROW 51002, 'Verify must be 0 or 1.', 1;
    IF @BackupRoot IS NULL OR LEN(@BackupRoot) > 100
       OR @BackupRoot NOT LIKE N'[A-Za-z]:\%'
       OR CHARINDEX(N'..', @BackupRoot) > 0 OR CHARINDEX(N'/', @BackupRoot) > 0
        THROW 51003, 'Use a local absolute backup root, up to 100 characters.', 1;
    WHILE RIGHT(@BackupRoot, 1) = N'\'
        SET @BackupRoot = LEFT(@BackupRoot, LEN(@BackupRoot)-1);
    IF LEN(@BackupRoot) < 4 THROW 51004, 'Do not use a drive root.', 1;
    IF NOT EXISTS (SELECT 1 FROM dbo.BackupWhitelist WHERE Enabled = 1)
        THROW 51005, 'Whitelist is empty; no backups were taken.', 1;
    IF @EncryptionCertificate IS NOT NULL AND NOT EXISTS
       (SELECT 1 FROM master.sys.certificates WHERE name = @EncryptionCertificate)
        THROW 51006, 'Encryption certificate is missing in master.', 1;

    DECLARE @RunId uniqueidentifier = NEWID(), @Database sysname,
            @AuditId bigint, @File nvarchar(260), @Sql nvarchar(max),
            @Stamp varchar(20), @Recovery nvarchar(60), @DatabaseId int,
            @State nvarchar(60), @SourceId int, @Failures int = 0,
            @LockResult int, @LockResource nvarchar(255), @Locked bit;
    DECLARE databases CURSOR LOCAL FAST_FORWARD FOR
        SELECT DatabaseName FROM dbo.BackupWhitelist WHERE Enabled = 1
        ORDER BY DatabaseName;
    OPEN databases;
    FETCH NEXT FROM databases INTO @Database;
    WHILE @@FETCH_STATUS = 0
    BEGIN
        SET @File = NULL;
        SET @Locked = 0;
        INSERT dbo.BackupAudit(RunId,DatabaseName,BackupType,StartedUtc,BackupRoot,Status)
        VALUES(@RunId,@Database,@BackupType,SYSUTCDATETIME(),@BackupRoot,'RUNNING');
        SET @AuditId = SCOPE_IDENTITY();
        BEGIN TRY
            IF @Database COLLATE Latin1_General_100_BIN2 LIKE N'%[^A-Za-z0-9_-]%'
               OR UPPER(@Database) IN
                  (N'CON',N'PRN',N'AUX',N'NUL',N'COM1',N'COM2',N'COM3',N'COM4',
                   N'COM5',N'COM6',N'COM7',N'COM8',N'COM9',N'LPT1',N'LPT2',N'LPT3',
                   N'LPT4',N'LPT5',N'LPT6',N'LPT7',N'LPT8',N'LPT9')
                THROW 51007, 'Whitelist name is not safe for this folder layout.', 1;
            SELECT @DatabaseId = NULL, @Recovery = NULL, @State = NULL, @SourceId = NULL;
            SELECT @DatabaseId=database_id, @Recovery=recovery_model_desc,
                   @State=state_desc, @SourceId=source_database_id
            FROM sys.databases WHERE name = @Database;
            IF @DatabaseId IS NULL THROW 51008, 'Whitelist database does not exist.', 1;
            IF @DatabaseId <= 4 THROW 51009, 'System databases are excluded.', 1;
            IF @State <> N'ONLINE' OR @SourceId IS NOT NULL
                THROW 51010, 'Database must be online and not a snapshot.', 1;
            IF @BackupType = 'LOG' AND @Recovery = N'SIMPLE'
                THROW 51011, 'SIMPLE recovery does not support log backups.', 1;
            IF EXISTS (SELECT 1 FROM sys.databases
                       WHERE database_id=@DatabaseId AND group_database_id IS NOT NULL)
                THROW 51012, 'Availability Group needs a replica-aware backup policy.', 1;
            -- FULL/DIFF serialize; LOG may run concurrently with a data backup.
            SET @LockResource = N'MeetAJ.Backup.' + @Database +
                CASE WHEN @BackupType='LOG' THEN N'.LOG' ELSE N'.DATA' END;
            EXEC @LockResult = sys.sp_getapplock
                @Resource=@LockResource, @LockMode='Exclusive',
                @LockOwner='Session', @LockTimeout=60000;
            IF @LockResult < 0 THROW 51013, 'Could not acquire the database backup lock.', 1;
            SET @Locked = 1;
            SET @Stamp = CONVERT(char(8),GETUTCDATE(),112) + '_' +
                         REPLACE(CONVERT(char(12),GETUTCDATE(),114),':','');
            IF LEN(@BackupRoot)+LEN(@Database)*2+LEN(@BackupType)+65 > 259
                THROW 51014, 'Backup path would exceed 259 characters.', 1;
            SET @File = @BackupRoot + N'\' + @Database + N'\' + @BackupType +
                        N'\' + @Database + N'_' + @BackupType + N'_' + @Stamp + N'_' +
                        CONVERT(nvarchar(36),NEWID()) +
                        CASE WHEN @BackupType='LOG' THEN N'.trn' ELSE N'.bak' END;
            UPDATE dbo.BackupAudit SET BackupFile=@File WHERE AuditId=@AuditId;
            SET @Sql = CASE WHEN @BackupType='LOG' THEN N'BACKUP LOG ' ELSE N'BACKUP DATABASE ' END
                + QUOTENAME(@Database) + N' TO DISK=@Path WITH '
                + CASE WHEN @BackupType='DIFF' THEN N'DIFFERENTIAL, ' ELSE N'' END
                + N'COMPRESSION, CHECKSUM, STOP_ON_ERROR, STATS=10'
                + CASE WHEN @EncryptionCertificate IS NULL THEN N'' ELSE
                    N', ENCRYPTION (ALGORITHM=AES_256, SERVER CERTIFICATE='
                    + QUOTENAME(@EncryptionCertificate) + N')' END + N';';
            EXEC sys.sp_executesql @Sql, N'@Path nvarchar(260)', @Path=@File;
            IF @Verify=1
            BEGIN
                SET @Sql = N'RESTORE VERIFYONLY FROM DISK=@Path WITH CHECKSUM, STOP_ON_ERROR;';
                EXEC sys.sp_executesql @Sql, N'@Path nvarchar(260)', @Path=@File;
            END;
            UPDATE dbo.BackupAudit
                SET Status='SUCCEEDED',FinishedUtc=SYSUTCDATETIME(),Verified=@Verify
                WHERE AuditId=@AuditId;
        END TRY
        BEGIN CATCH
            SET @Failures += 1;
            UPDATE dbo.BackupAudit SET Status='FAILED',FinishedUtc=SYSUTCDATETIME(),
                ErrorNumber=ERROR_NUMBER(),ErrorMessage=ERROR_MESSAGE()
                WHERE AuditId=@AuditId;
        END CATCH;
        IF @Locked=1
            EXEC sys.sp_releaseapplock @Resource=@LockResource, @LockOwner='Session';
        FETCH NEXT FROM databases INTO @Database;
    END;
    CLOSE databases;
    DEALLOCATE databases;
    IF @Failures > 0
        THROW 51015, 'One or more backups failed. Check DBAOperations.dbo.BackupAudit.', 1;
END;
GO

Create Backup Folders with PowerShell

Save this as C:/DBA/Prepare-SqlBackupFolders.ps1. It reads active whitelist members and creates FULL, DIFF and LOG directories. Invalid Windows names and reparse-point paths such as junctions are rejected.

02-prepare-folders.ps1 
# Windows PowerShell 5.1. Provision folders without enabling xp_cmdshell.
param([string]$ServerInstance = 'localhost', [string]$BackupRoot = 'D:\SQLBackup')
$ErrorActionPreference = 'Stop'
$rootPath = [IO.Path]::GetFullPath($BackupRoot).TrimEnd('\')
if ($rootPath -notmatch '^[A-Za-z]:\\.+' -or $rootPath.Length -gt 100) {
    throw 'Use a local absolute backup folder, not a drive root.'
}
function Assert-NoReparsePath([string]$Path) {
    $currentPath = [IO.Path]::GetFullPath($Path)
    while ($currentPath) {
        if (Test-Path -LiteralPath $currentPath) {
            $item = Get-Item -LiteralPath $currentPath -Force
            if ($item.Attributes -band [IO.FileAttributes]::ReparsePoint) {
                throw "Reparse points are not permitted: $currentPath"
            }
        }
        $parent = [IO.Directory]::GetParent($currentPath)
        if ($null -eq $parent) { break }
        $currentPath = $parent.FullName
    }
}
Assert-NoReparsePath $rootPath
$builder = New-Object System.Data.SqlClient.SqlConnectionStringBuilder
$builder.DataSource = $ServerInstance
$builder.InitialCatalog = 'DBAOperations'
$builder.IntegratedSecurity = $true
$builder.Encrypt = $true
$builder.TrustServerCertificate = $false
$connection = New-Object System.Data.SqlClient.SqlConnection $builder.ConnectionString
try {
    $connection.Open()
    $command = $connection.CreateCommand()
    $command.CommandText = 'SELECT DatabaseName FROM dbo.BackupWhitelist WHERE Enabled=1;'
    $reader = $command.ExecuteReader()
    $databases = @()
    while ($reader.Read()) { $databases += $reader.GetString(0) }
    $reader.Close()
    if ($databases.Count -eq 0) { throw 'Whitelist is empty.' }
    foreach ($database in $databases) {
        if ($database -notmatch '^[A-Za-z0-9_-]+$' -or
            $database -match '^(CON|PRN|AUX|NUL|COM[1-9]|LPT[1-9])$' -or
            $database -in @('master','model','msdb','tempdb')) {
            throw "Unsupported database folder name: $database"
        }
        foreach ($kind in @('FULL','DIFF','LOG')) {
            $directory = Join-Path (Join-Path $rootPath $database) $kind
            Assert-NoReparsePath $directory
            [IO.Directory]::CreateDirectory($directory) | Out-Null
        }
    }
} finally { $connection.Dispose() }

Create a Windows credential and SQLBackupFiles proxy under Agent → Proxies → Operating System (CmdExec). The proxy needs DBAOperations connectivity, SELECT on BackupWhitelist/BackupAudit and appropriate filesystem permissions. Enter the credential password in the secure credential interface, never the article script or job. Authorize the job owner to use this proxy. 

powershell.exe -NoProfile -NonInteractive -File "C:\DBA\Prepare-SqlBackupFolders.ps1" -ServerInstance "localhost" -BackupRoot "D:\SQLBackup"

Build Agent jobs and test manually

  1. In SSMS, open SQL Server Agent → Jobs → New Job. Use a clear name such as MeetAJ - SQL FULL and a trusted owner.
  2. Create the first step as Operating system (CmdExec), Run as SQLBackupFiles, running Prepare-SqlBackupFolders.ps1. Success advances to the next step. Failure quits with failure.
  3. Create the second step as Transact-SQL in DBAOperations. Use EXEC dbo.usp_BackupWhitelist @BackupType='FULL'. The other jobs use DIFF and LOG. Success quits successfully. Failure quits with failure.
  4. Schedule FULL daily at 01:00. Schedule DIFF every six hours from 07:00 through 19:00: exactly 07:00, 13:00 and 19:00. Schedule LOG every fifteen minutes from 00:00 through 23:59:59.
  5. Keep jobs disabled initially. Run preparation/FULL manually, then test DIFF/LOG. Use Start Job at Step. A disabled schedule does not prevent manual starts.
  6. Inspect each step in View History and compare BackupAudit, files and msdb.backupset. Overall job status is insufficient.

The equivalent script creates three disabled jobs/schedules without overwriting existing jobs. Adjust ServerInstance in the preparation step for named instances/certificate names. Configure Database Mail before replacing @Operator with an actual operator. Official documentation

03-agent-jobs.sql 
-- Provision SQLBackupFiles CmdExec proxy first; see article prerequisites.
-- Save 02-prepare-folders.ps1 as C:\DBA\Prepare-SqlBackupFolders.ps1.
USE msdb;
GO
DECLARE @Proxy sysname=N'SQLBackupFiles', @Operator sysname=NULL,
        @Owner sysname=SUSER_SNAME(), @Notify int,
        @Type varchar(4), @Job sysname, @Schedule sysname, @Command nvarchar(max),
        @Start int, @End int, @SubType int, @SubInterval int;
IF NOT EXISTS (SELECT 1 FROM dbo.sysproxies WHERE name=@Proxy AND enabled=1)
    THROW 51100, 'Create the enabled SQLBackupFiles CmdExec proxy first.', 1;
IF @Operator IS NOT NULL AND NOT EXISTS
   (SELECT 1 FROM dbo.sysoperators WHERE name=@Operator AND enabled=1)
    THROW 51101, 'Configured notification operator does not exist.', 1;
IF EXISTS (SELECT 1 FROM dbo.sysjobs
           WHERE name IN (N'MeetAJ - SQL FULL',N'MeetAJ - SQL DIFF',N'MeetAJ - SQL LOG'))
    THROW 51102, 'Jobs already exist. Review/update them; do not overwrite.', 1;
SET @Notify=CASE WHEN @Operator IS NULL THEN 0 ELSE 2 END;
BEGIN TRY
    BEGIN TRANSACTION;
    DECLARE types CURSOR LOCAL FAST_FORWARD FOR
        SELECT Kind FROM (VALUES ('FULL'),('DIFF'),('LOG')) t(Kind);
    OPEN types;
    FETCH NEXT FROM types INTO @Type;
    WHILE @@FETCH_STATUS=0
    BEGIN
        SET @Job=N'MeetAJ - SQL '+@Type;
        SET @Schedule=@Job+N' schedule';
        -- Jobs stay disabled until a manual FULL/DIFF/LOG test succeeds.
        EXEC dbo.sp_add_job @job_name=@Job, @enabled=0,
            @owner_login_name=@Owner, @notify_level_email=@Notify,
            @notify_email_operator_name=@Operator;
        EXEC dbo.sp_add_jobstep @job_name=@Job, @step_id=1,
            @step_name=N'Prepare whitelist folders', @subsystem=N'CmdExec',
            @proxy_name=@Proxy,
            @command=N'powershell.exe -NoProfile -NonInteractive -File "C:\DBA\Prepare-SqlBackupFolders.ps1" -ServerInstance "localhost" -BackupRoot "D:\SQLBackup"',
            @on_success_action=3, @on_fail_action=2, @retry_attempts=0;
        SET @Command=N'EXEC dbo.usp_BackupWhitelist @BackupType='''+@Type+
            N''', @BackupRoot=N''D:\SQLBackup'', @Verify=1;';
        EXEC dbo.sp_add_jobstep @job_name=@Job, @step_id=2,
            @step_name=N'Backup and verify', @subsystem=N'TSQL',
            @database_name=N'DBAOperations', @command=@Command,
            @on_success_action=1, @on_fail_action=2, @retry_attempts=0;
        SET @Start=CASE @Type WHEN 'FULL' THEN 010000 WHEN 'DIFF' THEN 070000 ELSE 000000 END;
        SET @End=CASE WHEN @Type='DIFF' THEN 190000 ELSE 235959 END;
        SET @SubType=CASE @Type WHEN 'FULL' THEN 1 WHEN 'DIFF' THEN 8 ELSE 4 END;
        SET @SubInterval=CASE @Type WHEN 'FULL' THEN 1 WHEN 'DIFF' THEN 6 ELSE 15 END;
        EXEC dbo.sp_add_jobschedule @job_name=@Job, @name=@Schedule,
            @enabled=1, @freq_type=4, @freq_interval=1,
            @freq_subday_type=@SubType, @freq_subday_interval=@SubInterval,
            @active_start_time=@Start, @active_end_time=@End;
        EXEC dbo.sp_add_jobserver @job_name=@Job, @server_name=N'(LOCAL)';
        FETCH NEXT FROM types INTO @Type;
    END;
    CLOSE types;
    DEALLOCATE types;
    COMMIT;
END TRY
BEGIN CATCH
    IF @@TRANCOUNT>0 ROLLBACK;
    THROW;
END CATCH;
GO

Job starts are asynchronous. Starting them consecutively does not ensure FULL finishes before DIFF. Run each separately and observe completion in History. Interrupted sessions/Agent outages can leave RUNNING audit records. Do not read these as success.

Cleanup while retaining the recovery-chain base

Deleting every file older than thirty days cannot guarantee the entire thirty-day recovery window. The base full and early required logs may precede the boundary. Deleting them invalidates part of the promised window.

Cleanup protects each database’s latest verified full before the retention boundary and all full/differential/log files since its start. It deletes only older files with valid extensions, whitelist-conforming paths and successful audit history. Extra hours or days may remain after failed full backups. This preserves recovery. Without a trustworthy base, nothing is deleted for that database.

Save as C:/DBA/Cleanup-SqlBackups.ps1. Preview is the default. Unknown, incomplete or FAILED files are not automatically removed. Investigate/manage them separately. This job does not purge audit or msdb history.

04-cleanup.ps1 
# Windows PowerShell 5.1. Default is preview; -Delete authorizes actual cleanup.
# Retain the verified FULL before the 30-day boundary, plus ALL backups since it.
[CmdletBinding(SupportsShouldProcess=$true)]
param(
    [string]$ServerInstance = 'localhost',
    [string]$BackupRoot = 'D:\SQLBackup',
    [ValidateRange(30,3650)][int]$RetentionDays = 30,
    [switch]$Delete
)
$ErrorActionPreference = 'Stop'
$rootPath = [IO.Path]::GetFullPath($BackupRoot).TrimEnd('\')
if ($rootPath -notmatch '^[A-Za-z]:\\.+' -or $rootPath.Length -gt 100) {
    throw 'Use a dedicated local backup root, not a drive root.'
}
function Assert-NoReparsePath([string]$Path) {
    $currentPath = [IO.Path]::GetFullPath($Path)
    while ($currentPath) {
        if (Test-Path -LiteralPath $currentPath) {
            $item = Get-Item -LiteralPath $currentPath -Force
            if ($item.Attributes -band [IO.FileAttributes]::ReparsePoint) {
                throw "Reparse point blocked: $currentPath"
            }
        }
        $parent = [IO.Directory]::GetParent($currentPath)
        if ($null -eq $parent) { break }
        $currentPath = $parent.FullName
    }
}
Assert-NoReparsePath $rootPath

$builder.IntegratedSecurity = $true
$builder.Encrypt = $true
$builder.TrustServerCertificate = $false

$candidates = New-Object System.Data.DataTable
try {
    $connection.Open()
    $command = $connection.CreateCommand()
    $command.CommandText = @'
DECLARE @Cutoff datetime2(3)=DATEADD(day,-@Days,SYSUTCDATETIME());
SELECT a.DatabaseName,a.BackupType,a.BackupFile,f.BackupFile AS AnchorFile
FROM dbo.BackupWhitelist w
CROSS APPLY (
    SELECT TOP (1) b.BackupFile,b.StartedUtc
    FROM dbo.BackupAudit b
    WHERE b.DatabaseName=w.DatabaseName AND b.BackupRoot=@Root
      AND b.BackupType='FULL' AND b.Status='SUCCEEDED' AND b.Verified=1
      AND b.FinishedUtc<=@Cutoff
    ORDER BY b.FinishedUtc DESC,b.AuditId DESC
) f
JOIN dbo.BackupAudit a ON a.DatabaseName=w.DatabaseName
WHERE w.Enabled=1 AND a.BackupRoot=@Root AND a.Status='SUCCEEDED'
  AND a.BackupType IN ('FULL','DIFF','LOG')
  AND a.FinishedUtc<f.StartedUtc AND a.FinishedUtc<@Cutoff
  AND a.BackupFile IS NOT NULL
ORDER BY a.DatabaseName,a.FinishedUtc;
'@
    $command.Parameters.Add('@Days',[Data.SqlDbType]::Int).Value=$RetentionDays
    $command.Parameters.Add('@Root',[Data.SqlDbType]::NVarChar,200).Value=$rootPath
    $reader=$command.ExecuteReader()
    $candidates.Load($reader)
    $reader.Close()
} finally { $connection.Dispose() }

foreach ($row in $candidates.Rows) {
    $database=[string]$row.DatabaseName
    $kind=[string]$row.BackupType
    if ($database -notmatch '^[A-Za-z0-9_-]+$' -or
        $database -in @('master','model','msdb','tempdb')) {
        throw 'Invalid database name in cleanup manifest.'
    }
    $expectedDir=Join-Path (Join-Path $rootPath $database) $kind
    $filePath=[IO.Path]::GetFullPath([string]$row.BackupFile)
    $anchorPath=[IO.Path]::GetFullPath([string]$row.AnchorFile)
    $anchorDir=Join-Path (Join-Path $rootPath $database) 'FULL'
    if (-not [IO.Path]::GetDirectoryName($filePath).Equals($expectedDir,[StringComparison]::OrdinalIgnoreCase) -or
        -not [IO.Path]::GetDirectoryName($anchorPath).Equals($anchorDir,[StringComparison]::OrdinalIgnoreCase)) {
        throw "Manifest path is outside the expected backup directory: $filePath"
    }
    Assert-NoReparsePath $filePath
    Assert-NoReparsePath $anchorPath
    if (-not (Test-Path -LiteralPath $anchorPath -PathType Leaf)) {
        throw "Protected FULL backup is missing; cleanup stopped: $anchorPath"
    }
    $extension=if ($kind -eq 'LOG') { '.trn' } else { '.bak' }
    if ([IO.Path]::GetExtension($filePath) -ne $extension -or
        -not [IO.Path]::GetFileName($filePath).StartsWith($database+'_'+$kind+'_',[StringComparison]::OrdinalIgnoreCase)) {
        throw "Unexpected backup filename: $filePath"
    }
    if (-not (Test-Path -LiteralPath $filePath -PathType Leaf)) { continue }
    $file=Get-Item -LiteralPath $filePath -Force
    if ($file.LastWriteTimeUtc -ge $cutoffUtc) { continue }
    if (-not $Delete) { Write-Output "PREVIEW: $filePath"; continue }
    if ($PSCmdlet.ShouldProcess($filePath,'Delete expired SQL backup')) {
        Remove-Item -LiteralPath $filePath -ErrorAction Stop
        Write-Output "DELETED: $filePath"
    }
}

Encryption and certificate/private-key recovery

Backups contain readable organizational data and need protection at rest/in transit. @EncryptionCertificate adds AES_256 using a master certificate. Provision the database master key/certificate under organizational key policy, then export the certificate/private key to protected storage separate from backup files. Without required keys, replacement-server restore fails. Official documentation

CHECKSUM improves error detection during page reads/backup writes. VERIFYONLY WITH CHECKSUM checks readability and existing checksums, but does not restore the database or establish logical integrity, application compatibility or RTO. Official documentation

Restore Testing on an Isolated Instance

  1. Prepare an isolated instance with adequate storage. Use destination names/paths distinct from production.
  2. Inspect backup type, DatabaseBackupLSN and FirstLSN/LastLSN with HEADERONLY. Read logical names using FILELISTONLY.
  3. Restore FULL using MOVE to test paths and NORECOVERY. Apply the latest compatible DIFF and required logs in order with NORECOVERY.
  4. For point-in-time recovery, apply STOPAT in the appropriate log step, finish with RECOVERY and run DBCC CHECKDB.
  5. Start test Jira/Confluence with matching Home/attachments. Record total recovery time and last-data difference against RPO/RTO.

Do not copy REPLACE or production paths as a generic restore command. Select actual generated backups and their logical filenames. Last month’s successful test does not prove today’s chain is recoverable.

Freshness, alerts and independent backup copies

  • Independent/off-site storage: retain local copies for speed and a second independent location. Keep at least one offline/immutable copy with separate identity so a compromised account cannot erase every version.
  • Restore drills: regularly test restore and point-in-time recovery for critical services. Record results, duration and corrective-action ownership.
  • Monitoring: check failures, missing/late backups per whitelist member, stale RUNNING records, free space, duration and off-site transfer. The validation example uses a twenty-minute log threshold. Align it to your RPO.
  • Alert delivery: configure approved Database Mail, select it in Agent Properties → Alert System and create an operator. Enable failure email and test a controlled failure. Cleanup needs separate notification. Independent monitoring must detect Agent itself stopping.
  • One chain owner: an ordinary full outside this pipeline can change the differential base. Use COPY_ONLY for ad hoc copies and coordinate other backup tools’ deletion/restore policies.
  • System databases and keys: this job excludes master/model/msdb/tempdb. Protect master/model/msdb, logins, jobs, certificates and runbooks separately. Management audit also needs its own retention/backup.
  • Capacity/performance: measure full size, differential growth and log generation. VERIFYONLY reads the entire file and adds IO. It may run in a separate validation job for large databases, provided Verified state and cleanup remain coordinated.
  • Change control: record whitelist additions, model/root changes and shorter retention. New databases have no coverage until explicitly added.

Before enabling schedules, verify whitelist database existence, engine/proxy rights, connection certificates, disk space, off-host transfer and a test restore. Report measured RPO/RTO to the service owner.

SQL Server Automated Backup FAQ

Why is log backup unavailable in SIMPLE?

SIMPLE reuses inactive transaction log after checkpoint when no blocker exists and does not maintain a backup log chain. LOG needs FULL/BULK_LOGGED and an initial data backup.

What follows a SIMPLE-to-FULL change?

Take a valid full/differential to establish the log chain. This scenario selects a fresh ordinary full, then schedules LOG. The same requirement does not apply identically to every model transition.

Does a differential store changes since the previous differential?

No. It covers changes since its ordinary full base. Restore the compatible full, latest appropriate differential and required logs in sequence.

Does VERIFYONLY replace a restore test?

No. It checks readability and existing checksums without restoring the database. CHECKDB, application validation and measured RTO remain necessary.

Why are some files older than thirty days retained?

The full before the retention boundary and its subsequent backups may be required for the entire window. Cleanup preserves these dependencies rather than deleting the base/required logs solely by age.

Which identities need backup-folder access?

The engine service writes/reads backups. A CmdExec proxy creates folders and performs cleanup here. Both require appropriate rights on the dedicated paths.

Does this job back up master, model, msdb or tempdb?

No. System databases are rejected even if whitelisted. Use separate jobs for master/model/msdb. Tempdb cannot be backed up.

Does Agent alone provide complete Jira/Confluence backups?

No. Back up Home, Shared Home, attachments and configuration with installed-version-compatible procedures. Independent off-site copies and application startup after restore are also required.
