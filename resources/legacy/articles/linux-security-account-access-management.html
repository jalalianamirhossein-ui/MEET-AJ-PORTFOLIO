Linux Access Management: Account Lifecycle, Restricted sudo and Offboarding

Build a Linux access model with personal accounts, command-specific sudo, negative permission tests and complete credential revocation.

Linux

Meet AJ technical article

Start reading

Introduction

Locking a password does not necessarily revoke access for a departing employee. SSH keys, tokens and existing sessions may remain valid. Access control must follow identity and account lifecycle.

Practical Example

Shift support can inspect Nginx status but cannot restart it or edit service files. Offboarding revokes bastion and VM access.

Prerequisites

Ubuntu Server 24.04 LTS, Bash 5 and systemd. Record installed package patches with dpkg-query before making changes.

Example lab capacity: 2 vCPUs, 2 GiB RAM and 20 GiB storage. These are planning assumptions, not vendor minimums; size the service for measured load.

Use sudo and OpenSSH with an administrator who has console access. opsreader and its permission mapping are examples. Organizational directory access needs a separate review of SSSD/LDAP configuration.

Architecture / Design

Identity → group → SSH admission → sudo command allowlist → audit. Separate human and service accounts, and use rotatable credentials for automation.

Installation / Configuration

Check that the name is available, then create the account without sudo-group membership.

getent passwd opsreader
sudo adduser opsreader
id opsreader
command -v systemctl
sudo visudo -f /etc/sudoers.d/opsreader-nginx

Place the complete rule below in the file. The systemctl path must match the host. --no-pager prevents privilege escape through an interactive pager.

opsreader ALL=(root) /usr/bin/systemctl --no-pager status nginx.service
sudo chmod 440 /etc/sudoers.d/opsreader-nginx
sudo visudo -cf /etc/sudoers
sudo -l -U opsreader
sudo -u opsreader sudo /usr/bin/systemctl --no-pager status nginx.service

Expect syntax OK and permission for only this exact command. An inactive service makes status return nonzero; that is not necessarily a permission error. In staging, also verify that a restart is denied.

Security Hardening

Do not grant broadly privileged shells, editors, package managers or wildcards as supposedly restricted sudo access: many can execute root code. Service accounts should not have interactive login. During offboarding, review keys, directory membership, API tokens, cron, sudo and active sessions. passwd -l locks only the password.

Monitoring

Forward sudo and SSH events from journalctl to central logging. Use auditd to monitor changes to /etc/passwd, /etc/group and /etc/sudoers.d. The UID-zero baseline should contain only the authorized account.

Troubleshooting

Use sudo -l to separate privilege failures from service errors. visudo -cf identifies parse problems. A user who logs in despite a locked password may be using a key.

sudo -l -U opsreader
sudo chage -l opsreader
loginctl list-sessions
getent group sudo
sudo journalctl _COMM=sudo -n 50 --no-pager

Distinguish directory access from local groups: identity caches and old sessions may persist until logout. Terminate a session only after confirming its user ID and assessing running jobs.

Backup / Recovery

Version policies, UID/GID mappings and permissions. Store shadow and private keys only in encrypted backups. Roll back this grant by removing its snippet and validating with visudo. Retain HOME according to policy during offboarding; revoke access and transfer organizational data to its owner.

Best Practices

Define permissions using exact commands and negative tests. Keep emergency credentials in a vault, personal accounts in the directory and changes linked to tickets.

Legacy Versions and Compatibility

usermod -aG sudo grants broad privileges and is unsuitable for this read-only role. Password locking is not equivalent to disabling every authentication method.

Frequently Asked Questions

Does passwd -l disable an SSH key?

No. Keys and other credentials require separate revocation.

Why include --no-pager in a sudo rule?

A pager may provide a shell using the privileges of the invoking command.
