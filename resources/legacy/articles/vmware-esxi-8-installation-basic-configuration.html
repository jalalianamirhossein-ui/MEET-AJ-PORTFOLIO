Install ESXi 8 and Configure Management and Recovery

Check hardware compatibility, install the image, configure VLANs/DNS/NTP and export configuration before adding workloads.

From installation to host acceptance

ESXi runs on hardware and manages VM resources. Before installation, match CPU, NICs, storage and firmware to the target build. After installation, validate management networking, DNS, NTP and datastores.

Boot, management and datastore paths

The boot device holds the operating system. Management VMkernel reaches its VLAN through a virtual switch and vmnic. Datastores hold VM data. Document failure and recovery paths for all three separately.

Example: add an empty host to a cluster

The new host has no workloads. Management uses VLAN 30, two uplinks and out-of-band console access. Run a canary VM before moving service VMs onto it.

Compatibility, image and installation disk

Select an approved ESXi 8 patch/OEM image and compatible vCenter. Match exact models, drivers and firmware to the Compatibility Guide.

Choose boot/datastore devices using build requirements. Detected NICs are not necessarily supported. Plan workload capacity separately from installation minimums.

Prepare console, credentials, license, DNS, NTP and VLANs. Installation overwrites the selected disk. Verify its serial before accepting the target.

Build and support conditions

This guide targets ESXi 8. Check lifecycle, entitlement and vCenter compatibility before deployment. Nested ESXi on Workstation does not validate physical hardware compatibility.

Install the image and configure DCUI

Match CPU/NIC/controller and firmware to the target build/OEM image. Record the ISO hash and verify the boot device by its serial.

Install on the designated boot device after identifying existing datastores and data-bearing disks. Use DCUI for first boot.

In F2 → Configure Management Network, select management NICs, the switch-compatible VLAN ID, static IP and DNS. Test gateway/DNS. Sample IP is 10.20.30.11/24 with gateway 10.20.30.1.

Open Host Client with the registered hostname and a valid certificate. Enable SSH temporarily for the change window only. Run these read-only ESXi Shell commands. 

vmware -v
esxcli system version get
esxcli network nic list
esxcli network ip interface ipv4 get
esxcli network ip route ipv4 list
esxcli system ntp get

Expect the target build, correct management IP and both uplinks as designed. Configure DNS/NTP and check start policy. Join vCenter, deploy a canary VM and validate networking, datastore and a test workload restart.

Restricted management and temporary SSH

Restrict management networks and use named least-privilege vCenter identities. Close SSH/Shell after changes. Test exceptions and console recovery before Lockdown Mode. Establish trusted certificate and syslog paths.

Host and storage health

Monitor uplinks, hardware sensors, host disconnects and storage latency through vCenter. Restrict monitoring API access. Check boot/datastore capacity and NTP too. Low CPU alone is not host health.

Lost management or datastore access

For management loss, inspect vmnic, VLAN and gateway through the console. Missing NICs require OEM-image and driver/compatibility checks. Investigate missing datastores through paths/controllers, not reformatting. 

esxcli storage core path list
esxcli network vswitch standard list
tail -n 80 /var/log/vmkernel.log
tail -n 80 /var/log/hostd.log

Align VMkernel and physical-switch tagging to the design. Double tagging breaks access. Correct certificate errors through DNS/chains rather than globally disabling validation.

Configuration bundles and VM backups

Create the bundle through temporary Shell access, download its returned URL from an approved workstation, then close the Shell. 

vim-cmd hostsvc/firmware/sync_config
vim-cmd hostsvc/firmware/backup_config

The bundle contains configuration, not VMs or datastores. Restore depends on build/UUID requirements. Keep image, licensing, VLAN and credential records off-host and follow the version’s replacement-host KB.

Test the host before service workloads

Use a canary to test network, storage and restart behavior. Keep firmware/driver patches aligned. Check target storage requirements before selecting older USB/SD boot media.

Frequently Asked Questions

Does a configuration backup include VMs?

No. VMs and datastores need separate backups.

Is a detected NIC necessarily supported?

No. Match model, driver, firmware and build to the compatibility matrix.
