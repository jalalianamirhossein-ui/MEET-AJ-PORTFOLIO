Detect Port Scans on MikroTik with psd

Configure TCP scan detection, inspect counters and address lists, and preserve legitimate router management.

MikroTik

Meet AJ technical article

Start reading

Where psd fits in the firewall

psd is a heuristic matcher for TCP and UDP scan patterns. This example explicitly selects protocol=tcp and inspects TCP only. Detection supplements default deny. A nonmatch does not establish safe traffic.

Detection and drop ordering

Handle established traffic and permitted management before the heuristic. The first rule temporarily records suspicious sources. The second drops their traffic. Earlier broad accepts prevent the matcher from running.

Router traffic versus transit traffic

Input rules protect the router itself. LAN or NAT-published servers require separate forward-policy checks. The sample exempts approved scanners from management subnet 10.20.30.0/24.

Inspect the existing rules

This example targets RouterOS v7. Record version and architecture and check the selected release’s syntax.

WAN must contain the actual WAN interfaces. Test on an isolated router or CHR using an authorized scanner. Measure CPU and connection tracking under load.

Use console or reliable management access. Keep an off-router export and use Safe Mode for rule edits. Replace the management address list with actual sources.

Heuristic limitations

psd is not an IDS. FastTrack primarily affects established forward traffic. A successful input rule does not establish forward or IPv6 protection.

Add rules and test counters

Inspect firewall order and WAN membership. Populate management sources with trusted actual values. Do not transfer sample values blindly into production policy. 

/interface list member print
/ip firewall filter print detail
/ip firewall connection tracking print
/ip firewall address-list add list=mgmt-approved address=10.20.30.0/24 comment="Approved management subnet"

Add rules in Safe Mode. Appending them alone is insufficient. In WinBox, place them after management accepts and before broad accepts/final drop. 

/ip firewall filter add chain=input in-interface-list=WAN protocol=tcp connection-state=new src-address-list=!mgmt-approved psd=21,3s,3,1 action=add-src-to-address-list address-list=port_scanners address-list-timeout=1h comment="ENT-SCAN detect"
/ip firewall filter add chain=input in-interface-list=WAN src-address-list=port_scanners action=drop comment="ENT-SCAN drop"
/ip firewall filter print stats where comment~"ENT-SCAN"
/ip firewall address-list print where list=port_scanners

Run an authorized lab TCP scan. Inspect detection/drop counters and the address list while testing management access. Avoid unlimited packet logs.

Zero counters and false positives

For zero counters, inspect rule order, WAN membership and the traffic’s actual chain. For false positives, examine shared NAT, request rate and timeout. Slow scans might stay below thresholds. UDP is outside this example because its rule selects TCP.

Allowlists, IPv6 and default deny

Allowlists require trusted paths. Spoofable WAN source addresses are not reliable exemptions. IPv6 needs separate rules. Restrict SNMP/public management and keep default deny independent of scan detection.

List size and connection-tracking pressure

Monitor detection/drop counters, address-list size, CPU and connection count. A scan surge with resource pressure matters more than an isolated scan. Avoid unlimited per-packet logging.

Undo rules without disabling the firewall

Disable only ENT-SCAN rules to undo the change. Match an erroneous entry’s IP and timing to the incident before removing it. Clearing the entire list loses detection evidence. 

/ip firewall filter disable [find where comment~"ENT-SCAN"]
/ip firewall address-list print where list=port_scanners

After rollback, repeat management and required-service tests through the original path. Keep the pre-change export off-device.

Traffic-appropriate thresholds

Do not treat the sample 21,3s,3,1 values as universal security settings. Test approved scanners and NAT-shared users positively and negatively, then tune timeout from results.

Frequently Asked Questions

Does input protect LAN servers?

No. Transit traffic requires a forward policy.

Does psd detect every scan?

No. It is a limited heuristic and does not replace default deny or an IDS.
