MikroTik Firewall: Detect Port Scans Without Blocking Management

Deploy scoped TCP scan detection with an approved management allowlist, temporary blocking, counter checks and false-positive review.

MikroTik

Meet AJ technical article

Start reading

Introduction

Scan detection is useful only if it preserves legitimate management access. The psd matcher is a TCP heuristic; default-deny rules and source restrictions remain the primary protection.

Practical Example

Security runs authorized scans from 10.20.30.0/24. ether1 belongs to WAN. The input chain protects the router; LAN services need a separate forward policy.

Prerequisites

MikroTik RouterOS v7. Record the exact patch and architecture with /system resource print. Review v6 commands before using them on v7.

Use a router or isolated CHR lab with separate interfaces. Measure CPU, RAM and connection tracking under representative load.

Connect from the management network with the required write policies. Before changing configuration, enable Safe Mode with Ctrl+X, save an off-device export and arrange independent console access.

Architecture / Design

WAN → established/related → management allowlist → psd → temporary list → drop. These rules supplement an existing ruleset; they do not constitute a complete Firewall.

Installation / Configuration

Inspect rule order and interface lists first. WAN and mgmt-approved must be defined; the sample allowlist is a lab subnet.

/interface list member print
/ip firewall filter print detail
/ip firewall connection tracking print
/ip firewall address-list add list=mgmt-approved address=10.20.30.0/24 comment="Approved management subnet"

Add these rules in Safe Mode. They are appended by default; use WinBox to place them after permitted management traffic and before a general new-connection accept or final drop.

/ip firewall filter add chain=input in-interface-list=WAN protocol=tcp connection-state=new src-address-list=!mgmt-approved psd=21,3s,3,1 action=add-src-to-address-list address-list=port_scanners address-list-timeout=1h comment="ENT-SCAN detect"
/ip firewall filter add chain=input in-interface-list=WAN src-address-list=port_scanners action=drop comment="ENT-SCAN drop"
/ip firewall filter print stats where comment~"ENT-SCAN"
/ip firewall address-list print where list=port_scanners

Test only with an authorized scanner in staging. Detection/drop counters should rise for a TCP scan without blocking the management subnet. Do not enable unlimited per-packet logging.

Security Hardening

Do not trust a management source address that can be spoofed from WAN; edge anti-spoofing matters. Failure to match psd does not authorize traffic. IPv6 needs independent rules. Restrict public management and SNMP access.

Monitoring

Monitor CPU, connection count, drop counters and list size. Alert on a scan surge accompanied by load; an isolated scan should not page an operator. Rate-limit logs and forward them through the protected management network.

Troubleshooting

Zero counters suggest rule ordering, WAN membership or traffic traversing forward instead of input. For false positives, inspect shared NAT/scanner behavior and timeout before lowering thresholds. Slow scans and UDP may evade psd; that is a design limitation.

Backup / Recovery

Keep Firewall backups and exports off-device. Roll back only this change’s rules rather than disabling the entire Firewall.

/ip firewall filter disable [find where comment~"ENT-SCAN"]
/ip firewall address-list print where list=port_scanners

Remove an individual list entry only after matching its IP to the incident. Clearing the whole list discards evidence.

Best Practices

Test input, forward and IPv6 independently. Place established traffic before the heuristic and document thresholds and timeouts against false-positive evidence.

Legacy Versions and Compatibility

psd is neither a comprehensive attack detector nor an IDS. FastTrack primarily affects established forward traffic; input results do not establish forward protection.

Frequently Asked Questions

Does input protect LAN servers?

No. Transit traffic requires a forward policy.

Does psd detect every scan?

No. It is a limited heuristic and does not replace default deny or an IDS.
