Back Up Network Device Configurations with Oxidized and Git

Install Oxidized, verify SSH host keys, store configurations in bare Git, and check backup freshness and device recovery.

Collect configuration and change history

Oxidized connects to devices, reads configuration through a model and stores changes in Git. Collected files must be complete and fresh. Validate restore against the actual model/firmware. File presence alone does not establish recoverability.

Ruby, models and device accounts

The baseline is Oxidized 0.37.0 with Ruby 3.2 on Ubuntu 24.04. Record application/resolved dependency versions and test models against device firmware.

Two vCPUs and 4 GiB RAM are starting examples. Size disk for Git history and threads for device latency and AAA capacity.

Use a non-login service account and device identities authorized for model-required commands. Restrict SSH to management. Verify read-only access through actual command authorization.

Pinned models and dependencies

IOS, RouterOS and SwOS have distinct models/transports. Pinning the main gem does not pin every dependency. Preserve resolved versions in artifacts or lockfiles for reproducible deployment.

From SSH to a bare repository

SSH supplies model output to Oxidized and Git stores versions. Remove_secret strips some secrets and limits restoration. Protect certificates, licenses and native device backups separately.

Example: hourly device polling

For 120 devices, hourly polling is an example. Monitor each node’s last successful fetch. No new commit might mean unchanged configuration rather than collection failure.

Known hosts and historical secrets

In 0.37.0, secure: true enables Net::SSH’s always host-key verification. Provision the service account’s known hosts with verified keys. Git history might retain old secrets. Restrict repositories/credentials and encrypt off-host copies. Do not expose optional REST/UI without authentication.

Install only a verified device host key

After the existing service account setup and before its first poll, collect candidate keys on a management workstation. Compare the SHA256 fingerprint with the device console or another authenticated inventory. ssh-keyscan alone does not authenticate a host. Do not install the candidate if it differs.

ssh-keyscan -T 5 core-sw01.corp.example.com > core-sw01.candidate
ssh-keygen -lf core-sw01.candidate -E sha256

Only after the comparison succeeds, transfer the approved file securely to the collector and run the following collector commands with sudo. Review any existing known_hosts first; the append is for one genuinely new approved host. Secure host-key verification must reject a deliberately mismatched key in staging.

sudo install -d -o oxidized -g oxidized -m 700 /var/lib/oxidized/.ssh
sudo sh -c 'cat core-sw01.candidate >> /var/lib/oxidized/.ssh/known_hosts'
sudo chown oxidized:oxidized /var/lib/oxidized/.ssh/known_hosts
sudo chmod 600 /var/lib/oxidized/.ssh/known_hosts

Install the gem, configuration and systemd unit

This lab example uses a fresh VM. Check executable location with command -v, install the approved gem and record actual versions. 

sudo apt-get update
sudo apt-get install -y ruby ruby-dev ruby-bundler build-essential libsqlite3-dev libssl-dev pkg-config cmake libssh2-1-dev libicu-dev zlib1g-dev libyaml-dev git
sudo gem install oxidized --version 0.37.0 --no-document
gem list oxidized
command -v oxidized
sudo useradd --system --create-home --home-dir /var/lib/oxidized --shell /usr/sbin/nologin oxidized
sudo install -d -o oxidized -g oxidized -m 700 /var/lib/oxidized/.config/oxidized

Pin the observed version and preserve its artifact before production rollout. Store complete config at /var/lib/oxidized/.config/oxidized/config with mode 600. Replace credentials with vault secrets. 

---
username: oxidized
password: REPLACE_WITH_DEVICE_READ_SECRET
model: ios
interval: 3600
timeout: 20
retries: 2
threads: 5
input:
  default: ssh
  ssh:
    secure: true
output:
  default: git
  git:
    user: Oxidized
    email: oxidized@example.com
    repo: /var/lib/oxidized/configs.git
source:
  default: csv
  csv:
    file: /var/lib/oxidized/.config/oxidized/router.db
    delimiter: !ruby/regexp /:/
    map:
      name: 0
      model: 1
vars:
  remove_secret: true

The sample router.db line is core-sw01.corp.example.com:ios. Verify DNS/SSH fingerprints through a trusted path and negatively test secure/strict-verification behavior for this input version. Permit model-required commands without assigning privilege 15 by default.

Before the foreground test, provision known hosts for the service identity. Ssh-keyscan collects keys but does not authenticate them. Compare fingerprints through the console before installing approved entries.

This is a foreground test. Substitute the actual executable path. Stop it after a successful poll, then install the unit with that same path. 

sudo -u oxidized env HOME=/var/lib/oxidized /usr/local/bin/oxidized
[Unit]
Description=Network configuration collection
After=network-online.target
Wants=network-online.target
[Service]
User=oxidized
Group=oxidized
Environment=HOME=/var/lib/oxidized
ExecStart=/usr/local/bin/oxidized
Restart=on-failure
RestartSec=10
UMask=0077
NoNewPrivileges=true
PrivateTmp=true
[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now oxidized
sudo -u oxidized git --git-dir=/var/lib/oxidized/configs.git log -1 --oneline
sudo -u oxidized git --git-dir=/var/lib/oxidized/configs.git ls-tree --name-only HEAD

Git output is commonly bare: cat on a working-tree path is inappropriate. Inspect ls-tree, then git show HEAD:node-name. Match successful logs to an actually collected node.

Fetch freshness differs from commit age

Record fetch duration, node failures and last successful fetch. Commit age is not poll freshness because unchanged configurations create no new commit. Two missed intervals are an example threshold. Active systemd state is insufficient.

Failed nodes and incomplete configuration

For failed nodes, check DNS, SSH, AAA and models. Bare repositories have no working tree, so use git show. Permission failures require service/path ownership checks. Verify changed host keys through a console. Incomplete output points to command authorization or parser behavior.

Restore a commit on matching hardware

Keep repositories, configuration, inventory and credential references off-host. Extract a known commit and review diff, syntax and interfaces on matching hardware. IP/interface changes risk management loss. Git exports do not contain all native device state.

Before adding a new model

Test full output and minimum model privileges on the actual firmware. If NetBox supplies inventory, convert its API response into Oxidized’s source schema. The formats differ.

For an inventory source of truth, review the NetBox installation guide. Related guide

Extract the exact collected object, not a nonexistent working file

sudo -u oxidized git --git-dir=/var/lib/oxidized/configs.git ls-tree --name-only HEAD
# Replace this object path with the exact name printed above.
sudo -u oxidized git --git-dir=/var/lib/oxidized/configs.git show HEAD:core-sw01.corp.example.com

Expect the model’s complete reviewed configuration; path not found means the object name differs or polling has not produced that object. Select an earlier known-good commit by its recorded hash for recovery. Output can contain secrets retained in history. Review commands and hardware/version compatibility offline before applying anything to a device.

Frequently Asked Questions

Why is there no config file to cat in the Git repository?

The output can be bare. Use git ls-tree and git show to read its objects.

Does an export fully restore a device?

No. Secrets, certificates, licenses and binary state may need separate backups.
