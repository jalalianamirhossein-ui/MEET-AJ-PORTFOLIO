Oxidized Network Backups: Versioned Configuration and Restore Tests

Deploy Oxidized with restricted device credentials, bare Git output, per-node freshness monitoring and model-specific recovery drills.

Introduction

A configuration file does not prove network recoverability. Record changes, alert on collection failures and test selective restore against actual device models.

Practical Example

120 switches/routers are polled hourly. Monitor each node’s last successful backup independently of process health.

Prerequisites

Ubuntu Server 24.04 LTS, Bash 5 and systemd. Record installed package patches with dpkg-query before making changes. Use Oxidized 0.37.0 with Ruby 3.2 on Ubuntu 24.04 from RubyGems, with the application version pinned by --version. Record resolved dependencies in an organizational artifact before production rollout. Validate device models against their firmware.

Suggested 2 vCPU, 4 GiB RAM and disk sized for history. Choose thread count from device latency and AAA load.

Ruby/Bundler and build dependencies; a non-login service identity, vault-provided read credentials and TCP/22 to device management only.

Architecture / Design

Device SSH → model parser → normalized configuration → bare Git → encrypted off-host copy. Secret removal can limit recovery; credentials and native binary backups need separate protection.

Installation / Configuration

This lab example uses a fresh VM. Check executable location with command -v, install the approved gem and record actual versions.

sudo apt-get update
sudo apt-get install -y ruby ruby-dev ruby-bundler build-essential libsqlite3-dev libssl-dev pkg-config cmake libssh2-1-dev libicu-dev zlib1g-dev libyaml-dev git
sudo gem install oxidized --version 0.37.0 --no-document
gem list oxidized
command -v oxidized
sudo useradd --system --create-home --home-dir /var/lib/oxidized --shell /usr/sbin/nologin oxidized
sudo install -d -o oxidized -g oxidized -m 700 /var/lib/oxidized/.config/oxidized

Pin the observed version and preserve its artifact before production rollout. Store complete config at /var/lib/oxidized/.config/oxidized/config with mode 600; replace credentials with vault secrets.

---
username: oxidized
password: REPLACE_WITH_DEVICE_READ_SECRET
model: ios
interval: 3600
timeout: 20
retries: 2
threads: 5
input:
  default: ssh
  ssh:
    secure: true
output:
  default: git
  git:
    user: Oxidized
    email: oxidized@example.com
    repo: /var/lib/oxidized/configs.git
source:
  default: csv
  csv:
    file: /var/lib/oxidized/.config/oxidized/router.db
    delimiter: !ruby/regexp /:/
    map:
      name: 0
      model: 1
vars:
  remove_secret: true

The sample router.db line is core-sw01.corp.example.com:ios. Verify DNS/SSH fingerprints through a trusted path and negatively test secure/strict-verification behavior for this input version. Permit model-required commands without assigning privilege 15 by default.

sudo -u oxidized env HOME=/var/lib/oxidized /usr/local/bin/oxidized

This is a foreground test. Substitute the actual executable path. Stop it after a successful poll, then install the unit with that same path.

[Unit]
Description=Network configuration collection
After=network-online.target
Wants=network-online.target
[Service]
User=oxidized
Group=oxidized
Environment=HOME=/var/lib/oxidized
ExecStart=/usr/local/bin/oxidized
Restart=on-failure
RestartSec=10
UMask=0077
NoNewPrivileges=true
PrivateTmp=true
[Install]
WantedBy=multi-user.target
sudo systemctl daemon-reload
sudo systemctl enable --now oxidized
sudo -u oxidized git --git-dir=/var/lib/oxidized/configs.git log -1 --oneline
sudo -u oxidized git --git-dir=/var/lib/oxidized/configs.git ls-tree --name-only HEAD

Git output is commonly bare: cat on a working-tree path is inappropriate. Inspect ls-tree, then git show HEAD:node-name. Match successful logs to an actually collected node.

Security Hardening

Do not expose optional UI/REST publicly; use an authenticated reverse proxy. Git history can retain previously removed secrets, so encrypt/restrict it. Evaluate read-only RouterOS/SwOS model access separately and avoid shared credentials across device groups.

Monitoring

Observe per-node last-success time, duration and failure counts. Send sensitive ACL/routing changes for ticket review, not automatic execution. Staleness beyond two intervals is an example threshold; systemd active is insufficient.

Troubleshooting

Failed nodes require DNS/SSH/AAA and firmware-model checks. Bare repos have no working tree; use git show. Repo permission failures require checking service ownership/UMask. For changed host keys, verify fingerprints at the console rather than disabling checks. Incomplete output suggests command authorization or parser issues.

Backup / Recovery

Encrypt and copy the repo, config, node inventory and credential references off-host. Extract a known commit and review diff/syntax on a matching spare model/firmware. Interface/IP changes can break management. Exports omit some keys, licenses and binary state; retain vendor-native backups too.

Best Practices

Require actual-model restore drills, dependency manifests and restricted privilege. Raw NetBox API responses need conversion to Oxidized source format; their schemas differ.

Legacy Versions and Compatibility

SwOS, RouterOS and IOS models/transports differ. 0.37.0 is the baseline; lock transitive dependencies in organizational artifacts as well.

Frequently Asked Questions

Why is there no config file to cat in the Git repository?

The output can be bare. Use git ls-tree and git show to read its objects.

Does an export fully restore a device?

No. Secrets, certificates, licenses and binary state may need separate backups.
