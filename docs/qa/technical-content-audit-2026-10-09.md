# Technical content audit — 2026-10-09

This report covers the new technical-content pass, relative to the already standardized/numbered source baseline. Earlier structural changes are documented in the [structure report](article-structure-audit-2026-10-09.md), [legacy prose report](legacy-article-prose-audit-2026-10-09.md) and [final numbering report](final-enterprise-article-audit-2026-10-09.md). No commit, push, deployment or production database operation was performed.

## Scope and measured changes

All **41 repository articles / 82 EN/FA editions** were inspected. **17 articles changed**: 15 had missing or insufficient operational instruction, one had a confirmed firewall command defect, and one had bilingual teaching-label defects. **One chapter was substantially rebuilt**: Windows network commands. The other 24 sources were retained after subject-specific review.

Added **46 command/configuration blocks** and **20 explicitly illustrative output blocks**, replacing three abbreviated Windows bundles. Four faulty MikroTik Drop rules and one NetBox coordinated-backup procedure were corrected. Five Persian-only TrueNAS teaching blocks were made language-neutral English; executable syntax stayed identical in both locales. There are **230 new paired explanatory/reference leaves**. Source preformatted blocks increased **593 → 656**; **655 visible technical artifacts** are contracted (the remaining block is authored SEO keywords, intentionally omitted by the existing renderer). Preformatted artifacts include commands, configurations, GUI paths, diagrams and illustrative output; this is not a count of executed commands.

No main sections were moved or renumbered in this pass. All old IDs, source image tags and complete `<head>` metadata stayed intact against the captured baseline. Source code differences are limited to the Windows rebuild, added examples, the four Drop rule fixes, the coordinated NetBox backup, and five TrueNAS teaching-label translations. No visible editorial review dates were introduced.

## Root cause and permanent fixes

The archived Windows source contained 17 code blocks; the maintained pre-audit source contained only four. The historical enterprise converter replaced the old body with abbreviated runbooks; its positional bilingual companion could not safely regenerate the expanded collection. Existing sanitization, localization and code presentation were traced and tested: no executable-code loss was reproduced in that path. The corrected entry points compile the reviewed maintained inputs instead of replacing articles from the archive.

`resources/content/article-technical-content.json` owns the reviewed bilingual changes. `scripts/article_technical_content.py` writes complete additions into existing source sections and invokes the existing shared ordering logic. TrueNAS teaching-label corrections also live in the Markdown input used by its generator. Repeated compilation is stable. `ArticleTechnicalContent` uses the same inputs solely for the content-only migration, across publication states without changing metadata or timestamps. Customized Windows CMS procedures are fingerprint-guarded and retained for explicit review; unknown CMS slugs are retained and flagged as unreviewed. The actual CMS migration was not executed.

The reviewed contracts identify complete examples in their actual procedure sections. Source and final Blade tests cannot satisfy a missing command with its name in prose. The read-only CMS auditor, source auditor and all-article browser check use those contracts; the confirmed Drop/limit error is checked separately so changing a hash cannot hide it. Comments are excluded from that executable-rule check. Existing ordering, duplicate IDs/headings, empty sections, repeated prose, review-date, bilingual and anchor checks remain active. Hashes prove content preservation, not vendor compatibility or successful execution.

## Windows command coverage

Twenty command cards cover `ipconfig`, `/all`, `/flushdns`, `/release`, `/renew`, `ping`, `tracert`, `pathping`, `nslookup`, `netstat -ano`, `arp -a`, `route print/add/delete`, `getmac`, `hostname`, `netsh`, `net use`, `net view` and PowerShell `Test-NetConnection`. Each card includes purpose/use case, syntax, a usable example, labeled abbreviated illustrative output, field/failure interpretation, permissions and operational precautions. Syntax and lifecycle scope follow [Microsoft Windows commands](https://learn.microsoft.com/en-us/windows-server/administration/windows-commands/windows-commands) and the distinct [Test-NetConnection parameter sets](https://learn.microsoft.com/en-us/powershell/module/nettcpip/test-netconnection?view=windowsserver2025-ps).

Five staged incident chapters cover the eight requested failure classes: DNS, connectivity, TCP ports, wrong gateway, routing, ARP/duplicate addressing, SMB and latency/loss. Documentation-only addresses and fictional hosts must be substituted with authorized endpoints. DHCP release/renew, route edits, cache clearing and share mappings are clearly distinguished from read-only checks. Passwords are prompted rather than placed in commands. Route rollback matches the exact added temporary entry; global route/ARP/SMB resets and SMB1 are not offered as shortcuts. No listed network-changing operation was run on this workstation.

Device firmware, enterprise permissions, PKI and actual restore/SLA evidence still require approved staging validation.
- The native MySQL-specific test is skipped without its database environment. Existing custom CMS procedures that fail the replacement fingerprint are deliberately retained and must be read by the operator before applying source replacement. Any CMS-only slug is reported as unreviewed rather than silently accepted.
- Legacy `net use`/`net view` Microsoft pages are explicitly identified as legacy syntax references; inspect `net help use/view` on the actual serviced build. Regular Windows 10 lifecycle and LTSC/ESU are distinguished.
- Some vendor page fetches failed (notably Fortinet guide routes and GNU manpages); alternative primary CLI/manpage sources were used. This audit does not certify permanent availability of every external URL. Local image/download existence and browser loading were tested.
